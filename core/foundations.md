# Foundations

> Core's foundations, compiled for the web: sizes and row heights, numbers and dates, the accessibility floor and the motion tokens. Generated by Core's Web compile; do not edit.

## Sizes and row heights

- **Size axis**: (v3)'s names and heights stay. The table is the shared mapping, not a rename.

  | (v3) `Size` | Ours | Hit target |
  | --- | --- | --- |
  | XSmall | 28 | 48 |
  | Small | 36 | 48 |
  | Medium | 48 | 48 |
  | Large | 56 | 56 |
  | XLarge (icon buttons only) | 64 | 64 |

- **Hit target**: 48 at every size, apart from the visible height.
- **A row's height is not a Control height**, nor is a bar's outer height (a Tab Bar's 95 holds the home indicator's inset and stays raw), though the platter inside a bar follows the rule above: a row's `Size` (List item's Small 48 · Medium 56, Table's and Accordion's 48 · 56 · 72) is its own min height and skips the table; 48 aliases `Sizing/hit-target`, 56 and 72 stay raw.
- **Row** (Checkbox `Type=Full-bleed` as the owner drew it, [checkbox.md](components/checkbox.md)): the one tappable row. Checkbox and Radio `Type=Full-bleed`, List item and `_Accordion header` each draw it under their own layer names and axes, never as an instance of a shared row Item. Container padding 0 · 8 › the row: HORIZONTAL, padding 0 · 8, gap 8, radius 12, min height 48 (the Hit target, named in `hitTargetLayer`, ADR 0003), `layer-01`, Active `layer-active-01`, Focus a 2 stroke inside › parts padded 12 · 0. The innermost parts set the top and bottom padding and the frames around them the sides, so text starts 16 in. A BOOLEAN `Bottom border` (on) draws a 1 `border-subtle` line 16 in from each side, none on Active or Focus. Replaced a full-width square row, which had replaced a pressed radius 8. Each component's own changes (`_Accordion header` drops the border) sit in its Inventory bullet.
- **Density**: no density mode, and no compact List item. Tappable rows are the Row above. A static row that nobody taps (one term and its detail) is a List item too, with no action: in code it renders as text, not a button. `Size` is a row's density: List item's one line is 48 · 56 at Small · Medium. 48, the Hit target, is the floor for any tappable row.

## Numbers and dates

- **Units follow the number**: `250,000.00 ฿`, `1,234.5678 หน่วย` (no-break space), `2.43%` (no space). Not th-TH currency style (`฿1,234.56`).
- **Decimals**: baht 2, always (`325,169.00 ฿`); NAV per unit 4 (in baht); units 4; percent 2. Whole baht only outside Value (quick-pick chips, copy). Rounding is the back end's.
- **Separators**: comma for thousands, period for decimals, in every unit. No `K` / `M` / `ล้าน` in Value.
- **Sign**: a Change figure shows `+` above zero, `-` (hyphen-minus) below, nothing at zero; on the figure only: the bracketed percent takes the figure's colour but no sign, `+28,166.81 ฿ (2.43%)`. A figure that isn't a change never shows `+`. Parentheses never mean negative.
- **`--`** is an Empty value: no figure (unavailable, not applicable, failed), with no sign or percent, in `text-secondary`; its unit stays after it (`-- ฿`, `-- หน่วย`, `--%`), so a column of `--` still says what it counts. Zero is `0.00`; loading in place is Skeleton.
- **Dates** in a Thai UI are Buddhist era: short `17 มี.ค. 69` (rows), long `17 มีนาคม 2569` (confirmations, documents). Time is 24-hour `11.30 น.`, joined `17 มี.ค. 69, 11.30 น.`.
- **Sign colour**: only a Change figure is coloured: `text-positive` above zero, `text-negative` below (green up, red down, as on SET), `text-secondary` at zero (not `text-disabled`). Everything else is `text-primary` whatever its sign: balance, cost, NAV, units, order amounts, dividends, fees, weight %. Colour never stands for status: (v2)'s dividend `+10,000` was green when Completed and primary when Created; both become `10,000.00 ฿` in `text-primary`, and a money movement takes its direction from the row's label. A Change figure always shows its sign, so colour is never the only cue.

## Accessibility

The floor every Core and Extension component spec meets and cites. The standard is **WCAG 2.2 AA**. Ratios are WCAG 2 contrast ratios, computed with the `dataviz` skill validator's `contrast()`, with an alpha token composited over the surface beneath it. APCA is not a gate.

- **Base surfaces**: `background-primary`, `background-secondary`, `layer-01` and `layer-02`, in each mode. A Semantic `Text/*`, `Icon/*`, `Support/*` or `Link/*` token passes on all four. A Component-scoped token passes on the background its spec pairs it with. `layer-03` and the `Field/field` fill count only where a spec puts content on them. Today `text-primary`, `text-secondary`, `text-placeholder` and `icon-secondary` pass on the field at 6.16:1 or more.
- **Contrast targets**:

  | What | Target |
  | --- | --- |
  | Text: every Semantic `Text/*` and `Link/*` token, and every text style below Title 3 | 4.5:1 |
  | Large text: Title 3 and up (Bold, 20 and over) and Display | 3:1, only for a Component-scoped token bound to large text alone |
  | Placeholder | 4.5:1 on the field fill over its surface |
  | Non-text that carries meaning: an icon-only glyph, a status icon, a state indicator (selected stroke, checkbox, radio, toggle), a chart mark | 3:1 against what touches it |
  | Focus ring | 3:1 against the surface beside it |
  | Disabled (`State=Disabled`, `text-disabled`, `button-disabled`) | none |
  | Decorative: hairlines (`border-subtle`), gridlines, `chart-axis`, Skeleton, a fill behind text that passes, and a Brand mark beside its name, a Logo (Brand marks) | none |

- **Disabled** means "can't interact" and nothing else. A figure or label the user must read is never in `text-disabled`, so Value's zero is `text-secondary` (Numbers and dates).
- **Filled fields** stand on conditions. The `Field/field` fill is 1.22–1.38:1 on every surface, so it can't be a field's only cue (WCAG 1.4.11). Each field (Text field, Select, Search field, Text area) also shows:
  - a visible label, or a leading icon at 3:1 (Search field's magnifier);
  - placeholder or value text inside, at 4.5:1;
  - stroke 2 at 3:1 or more for Focus, Active and Error (`border-strong` is 13:1 or more).
  
  Amount field's box-less hero is its own digits. Visual direction's filled fields stand (Visuals).
- **Colour is never the only cue** (WCAG 1.4.1):
  - a Status carries an icon and text;
  - a gain or loss carries its sign (Numbers and dates);
  - selected shows a stroke 2 or an indicator, not only a fill change;
  - an error shows an icon and a message;
  - charts follow Chart tokens.
  - An inline link in running text is underlined: `link-primary` is 1.67:1 against `text-primary`. A standalone Link is not underlined, except in Breadcrumbs, where the underline is what tells a link from the current page.
- **Colour-blind check**: Chart tokens' check is the rule for every categorical palette, in Core or an Extension. Domain sets pass through their aliases. Super sector aliases Primitives directly, so it runs the check on its own steps, adjacent pairs in slice order with the family boundaries and the wrap. Chart marks need 3:1 against `layer-01` and against any other surface the chart sits on, or else visible labels or a table view.
- **Focus ring**: the indicator for keyboard and switch focus, on the web.
  - Geometry: 2 px `Focus/focus` outside the Container, with a 2 px gap that shows the surface. Its corners follow the Container's radius plus 4, so a Capsule's ring stays a Capsule.
  - Contrast: `Focus/focus` (Indigo/65) is 3.89:1 or more on every Base surface (Light 4.35 / 3.89, Dark 5.17 / 6.24 / 4.49). Inside a Container it would fail (1.88:1 on Dark `button-primary`), which is why it sits outside.
  - It is not Text field's `State=Focus`, which means the field is being edited.
- **Smallest text**: 11 pt (Caption 2, Icon 2XSmall); nothing smaller. Thai is 12 or larger, 13 where it wraps (Localisation).
- **Motion**: Reduce Motion (Android's remove animations, web's `prefers-reduced-motion`) is honoured.
  - Every animation has a reduced form: a crossfade or none.
  - Skeleton stops shimmering; Loading keeps turning.
  - Nothing means something only through motion.
  - Nothing flashes more than 3 times a second.
  - Content that moves on its own for over 5 s can be paused.
  - Motion tokens, each transition's reduced form and haptics: Motion and haptics.
- **Hit target**: 48 at every size (ADR 0003), which also meets WCAG 2.5.8's 24 px spacing.

## Motion

- **Motion tokens** are Carbon's six durations with its three productive easings. A spec writes them as `<duration> · <easing>`, e.g. `moderate-01 · standard`.

  | Duration | Android + web | Used for |
  | --- | --- | --- |
  | `fast-01` | 70 ms | a state change in place: press, hover, selected, a toggle's thumb, a field's stroke |
  | `fast-02` | 110 ms | a fade, a crossfade, a small surface leaving |
  | `moderate-01` | 150 ms | a small expansion: an accordion row, a progress step filling |
  | `moderate-02` | 240 ms | a small surface arriving: Snackbar, Toggletip, Alert and Menu |
  | `slow-01` | 400 ms | a large surface arriving: Sheet and Action Sheet |
  | `slow-02` | 700 ms | a scrim dimming in behind a sheet or dialog |

  | Easing | Curve (Android + web) | Used for |
  | --- | --- | --- |
  | `standard` | `cubic-bezier(0.2, 0, 0.38, 0.9)` | something that changes and stays on screen |
  | `entrance` | `cubic-bezier(0, 0, 0.38, 0.9)` | something arriving |
  | `exit` | `cubic-bezier(0.2, 0, 1, 0.9)` | something leaving |

  A surface that moves also names its **Movement** after the token, from Carbon's motion surfaces (`@carbon/motion@11.56.0`, `tokens/surfaces.tokens.json`), e.g. `moderate-02 · entrance · scale-in`. A change that stays in place (a state change, a fade, a scrim) names none.

  | Movement | Amount | Used for |
  | --- | --- | --- |
  | `scale-in` | scale 0.96 → 1, with opacity | a small surface opening from its anchor: Toggletip, Menu and Alert |
  | `slide-full` | the surface's own height, from the edge it is anchored to | a surface that comes in from an edge: Snackbar, Sheet and Action Sheet |
  | `expand` | height 0 → its content, with opacity | content opening in place: Accordion |

  - Leaving runs the same Movement in reverse.
  - ADS's 0.95 scale and 8 / 4 px slides are not used (ads-tokens.md § 5, D6).
  - Leaving takes the `exit` easing and the next shorter duration than the arrival: a `moderate-02` arrival leaves in `moderate-01`. A scrim fades out with the surface.
  - Carbon's expressive curves and `.bouncy` are not used in Core.
- **Reduced-motion form** (Reduce Motion, Android's remove animations, web's `prefers-reduced-motion`):
  - movement (a Movement, a thumb's travel, a selection sliding) becomes a `fast-02 · standard` crossfade, or no animation where the change is small;
  - colour and opacity changes may stay;
  - Skeleton stops shimmering and shows its static shape; Loading keeps turning;
