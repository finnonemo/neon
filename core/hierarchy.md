## Rules every component keeps

Rules 1–4 bind actions: Buttons, Icon buttons, Rect buttons. On a tag or a heading, `Hierarchy` is visual emphasis only, and those rules don't apply (H5).

1. **One Primary per context.** Context means a screen, a sheet, a dialog, or one panel of a multi-panel web tool. A component that nests a Primary counts toward its screen's one (H1).
2. **Style, not size, marks the preferred choice.** Buttons that sit side by side use the same `Size`. The preferred one takes the louder `Hierarchy` (Apple).
3. **Secondary is the default.** Reach for Secondary unless the action is the screen's one main action (Primary) or a way out (Tertiary). Uber says "Secondary buttons handle most actions".
4. **Tertiary is for ways out**: Cancel, Dismiss, Skip, Not now, Go back. A dismissive action is never Secondary.
5. **Destructive is `Type=Danger`, not a Hierarchy.** It is only for actions that permanently remove data. Logging out or cancelling a task is not destructive (H2).
6. **Don't use Disabled to say something is missing.** Keep the button enabled and show an error when it is tapped. If it must be Disabled, say why next to it.
