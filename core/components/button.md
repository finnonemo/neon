# Button

> Core's Button, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

```
Button | Rect button (variant root)   Hug × Hug, no fill, no padding; min width and height Interactive/<Size>, Container centred
└─ Container                          HORIZONTAL, Hug × Hug, min height Button/Container/<Round | Rect>/<Size>/Layout height (Fixed on Loading), centred, stroke 2 on Focus
   ├─ Artwork                         instance, hidden; shown by `Artwork`, swapped by `Leading artwork` (default Avatar 3XSmall, 18 × 18); hugs; opacity 45% on Disabled; none on Loading and Skeleton
   ├─ Leading Icon                    TEXT glyph (Icons library), shown by `Leading Icon`
   ├─ Label                           TEXT, `Label Text`
   ├─ Trailing Icon                   TEXT glyph, shown by `Trailing Icon`
   └─ _Loading                        instance, State=Loading only, Size pinned Medium
```

`Large (Expressive)` / `Medium (Expressive)`: Container min width 256 (`Layout width`), content centred; the `Trailing Icon` is absolute, pinned right × centre.

## Usage

- It has no Focus ring example yet.
- `Button` for every new nester; pin `iOS` (ADR 0005). `Rect button` stays for the screens that use it today; new sets don't nest it (Variant axes).
- Which `Hierarchy` and `Type` to pick, pairs and the destructive flow: Hierarchy below.
- Brand only on Primary. Danger for a destructive action: Secondary Danger at the entry point, Primary Danger only on the confirmation step ([H2](../hierarchy.md), owner 2026-11-09; replaces "prefer Primary Danger until the contrast issue is fixed"). Secondary Danger passes contrast since 2026-11-09 (Accessibility item 1).
- Expressive for a fixed 256 action; a full-width button is the nester's Fill.
- Leading artwork: turn `Artwork` on and `Leading Icon` off, then swap the artwork into `Leading artwork`. An artwork is at most 20 tall at XSmall and 24 at the other Sizes; a taller one grows the capsule. The gap to the Label is the Container's (4 · 8). A Donut is swapped in from the Charts library in the product file: it can't be a preferred value (ADR 0009). First case: Port's Today chip, Donut `Size=Small` with one segment per asset class ([donut.md](donut.md), Usage).
- Tertiary Inverse only on `Background/background-inverse` (Snackbar), for a single quiet action or Close; Primary Inverse there for a filled call (P2).
- Primary and Secondary Inverse are also the white buttons over maps, photos and headers; Toolbars, Tab bars and Segmented controls use them on `iOS=False`. Primary Inverse on `iOS=False` carries the effect style `Elevation/Button inverse` (Elevation). In Dark both are dark grey (`Grey/90`, `Grey/80`), following `background-secondary` and `background-tertiary`.

### Hierarchy

What each `Hierarchy` and `Type` is for. The words, the rules every component keeps and the owner's calls H1–H4 are in [hierarchy.md](../hierarchy.md); this section adds Button's own. Sources: Uber Base [Button, Usage](https://base.uber.com/6d2425e9f/p/756216-button/b/336373) and [Content](https://base.uber.com/6d2425e9f/p/756216-button/b/49b497), Apple HIG [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), read 2026-11-09.

Covers `Button`, `Icon button` and `Rect button`. All three have `Hierarchy` Primary · Secondary · Tertiary and `Type` Default · Brand · Danger (Inverse on Button and Icon button).

| `Hierarchy` | Use for | Don't | Label (Uber Content) | Apple role |
| --- | --- | --- | --- | --- |
| **Primary** | The one action the user is most likely to take in this context: moving forward in a flow, acknowledging and dismissing, or finishing a task. It is usually pinned at the bottom (Button dock). A sheet or a top toolbar may hold one too. | Don't put two on one screen. Don't put one in the middle of scrolling content; use Secondary there. | An imperative, verb + object: "Request UberX", "Confirm price", "Try again", "Save", "Next", "Got it". No "now". | Primary (default / Return), unless the action is destructive |
| **Secondary** | Most actions. Supporting actions next to content, inline in List items and rows, and most Icon buttons, since the grey fill keeps them visible and accessible. | Not for dismissive actions. | Short, with no noun when the button sits next to its object: "Edit", not "Edit address". | Normal |
| **Tertiary** | Dismissive actions that give a way out: Cancel, Dismiss, Skip, Not now, No thanks, Go back. It pairs with a Primary as the opposite action. | Not a quiet Primary. Not an Icon button standing alone on the page ([H3](../hierarchy.md)). | The inverse verb of the Primary: "Keep reservation" for "Cancel reservation". Never "Cancel" when the task itself is cancelling. Never Yes / No. | Cancel, when it cancels |

#### Type with Hierarchy

| `Type` | With | Use for |
| --- | --- | --- |
| Default | all | standard actions |
| Brand | Primary only | branded moments such as a membership (Uber's OnBrand) |
| Danger | Secondary, then Primary | destructive actions: Destructive flow |
| Inverse | Primary · Secondary · Tertiary | on `background-inverse` (Snackbar) and over maps, photos and headers, where a floating, background-safe button is needed (see above) |

#### Pairs

- **Opposite actions**: Primary + Tertiary, side by side and the same `Size`, e.g. Continue order / Cancel order. The Primary may be the destructive one, as in a confirmation step.
- **Related actions**, e.g. End ride / Unlock: Uber names the pair but its tab didn't render, so it gives no Hierarchy for it. The owner's pick is Primary + Secondary, which is Button dock's stack ([H4](../hierarchy.md)).
- Never two Primaries, and never Secondary + Secondary for a main action plus its way out.

#### Destructive flow

Uber's flow, and our recommendation ([H2](../hierarchy.md)):
1. The entry point (a row's or a screen's Delete) is **Secondary Danger**. It signals caution without being the main action.
2. A confirmation dialog or sheet follows. It says exactly what will be removed, and its final action is **Primary Danger**, paired with a Tertiary way out.
3. Secondary Danger passes contrast since 2026-11-09 (Accessibility item 1), so the entry point carries no known defect.
4. Apple: a destructive button never gets the default (Return) role, even when it is the likely choice. In code, Primary Danger is styled loud but is not the default button.

#### States that carry meaning

- **Disabled**: avoid it ([rule 6](../hierarchy.md)). Disabled does not explain what is missing.
- **Loading**: for an action that doesn't finish at once. The button stays where it is and shows the indicator. Apple allows a changed label next to the indicator ("Checkout" → "Checking out…"); that text is the nester's.
- **Focus, Hover, Active**: feedback only. They never change a button's Hierarchy.
