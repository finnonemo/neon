# Selection tag

> Core's Selection tag, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

Unchanged but for the four BOOLEANs and the `Leading Image` and `Remove` layers (2026-11-09):

```
Selection Tag (variant root)
└─ Container           HORIZONTAL; fill, stroke INSIDE, padding, gap, height and radius bound to Tag/Container/<Size>
   ├─ Leading Image    Avatar instance `Artwork=Image`, Badge off: `2XSmall` 24 at Large, `3XSmall` 18 at Medium and Small (20 until the owner cut it, 2026-11-09); exposed; visible = BOOLEAN `Leading Image`; no layer at XSmall
   ├─ Leading Icon     TEXT `add`; visible = BOOLEAN `Leading Icon`
   ├─ Label            TEXT
   ├─ Trailing Icon    TEXT `angle-down`; visible = BOOLEAN `Trailing Icon`
   └─ Remove           TEXT `xmark`, Trailing Icon's style and fill; visible = BOOLEAN `Remove`; every Size
```

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Color` | White · Yellow · Navy · Light Grey · Green · Blue · Purple · Red · Orange · Indigo | the `Tag/<Color>/…` tokens |
| `Hierarchy` | Primary · Secondary · Tertiary | the `Tag/<Color>/<Hierarchy>/…` tokens |
| `State` | Enabled · Hover · Disabled | fill step; Disabled tokens |
| `Size` | Large · Medium · Small · XSmall | `Tag/Container | Label | Icon/<Size>`: 40 · 32 · 24 · 20, radius 8 · 8 · 4 · 4 |
| `Selected` | False · True | the ring's colour and weight (added 2026-11-02) |

10 × 3 × 3 × 4 × 2 = **720 variants**. Properties: BOOLEAN `Leading Icon` and `Trailing Icon`, on by default, as Button's and Display tag's (owner, 2026-11-09); BOOLEAN `Leading Image`, off by default; BOOLEAN `Remove`, off by default. Grid: columns `Size`; rows `Color`, `Hierarchy`, `Selected`, then `State` innermost (Grid order; `Selected` was innermost until pawisssh/design-system#655).

## Usage

- A tag someone taps to filter content, to include or exclude a preference, or as an entered term in a search input (Uber Tag Usage). For a status or attribute nobody taps, use [Display tag](display-tag.md).
- Place it close to, or inside, the input that adds and removes it. If people can dismiss a tag, give them an easy way to add it back (Uber Tag Usage).
- Label (Uber Content): 1–2 words, one line; nouns, adjectives, places, distances; no verbs. A screen reader reads it as a button, with a label for each action it offers ("Double-tap to add", "Tap to delete") (Uber Spec and Content).
- Leading Image: a photo or logo before the Label, such as a person or a fund. Turn `Leading Image` on and `Leading Icon` off, then set the photo on the nested `Leading Image` Avatar. Large, Medium and Small only; XSmall has no image. The chip keeps its height and padding and grows 4–9 wider.
- SelectChip: `Trailing Icon` on (`angle-down`), `Leading Icon` off. The whole chip opens a Menu `iOS=False` 4 below it, the chosen item checked; the chip is `Selected=True` while the Menu holds a value other than the default ("All"). The chevron is not a button of its own. Roles: a button that opens a menu (`aria-haspopup="menu"`, `aria-expanded`).
- Removable chip: `Remove` on, `Trailing Icon` off (one or the other, never both). The remove is a button of its own, named "ลบ <label>" ("Remove <label>"), focused after its chip; code gives it a 44 × 44 pt (iOS) or 48 × 48 dp (Android) tap area centred on the glyph. Keep 8 or more between removable chips at Medium and above, 12 at Small and XSmall, or stand one alone.
- Which `Hierarchy` to pick: Hierarchy below.

### Hierarchy

How loud a tag is, not how important an action is. The words, the rules every component keeps and the owner's calls are in [hierarchy.md](../hierarchy.md); under [H5](../hierarchy.md) (the owner, 2026-11-09) rules 1–4 bind actions only, so on a tag `Hierarchy` is visual emphasis. Display tag's [DT1 and DT2](display-tag.md) apply here too. Sources: above, read 2026-11-09. A rule marked **(rec.)** is our recommendation, not a source's. The sources give no use per value for selection tags, so most of the table is **(rec.)**.

**Matched to Uber's Tag, Selection tags.** Uber's Tag page names two types, "Display tags" and "Selection tags": our two sets. The look is its `Behavior=Selection` (Kind and route). Uber's component index lists no Chip under Action, Input & control, Data display or Feedback & status; Badge is a count or a dot. Apple has no tag on iOS: the nearest is a button that behaves like a toggle (Toggles). Its token field is macOS only.

| `Hierarchy` | Use for | Don't | Uber · Apple |
| --- | --- | --- | --- |
| **Primary** | Uber: an actionable tag, with Secondary (Spec). **(rec.)** A filter bar that is the view's main way to narrow its content, such as the row above search results; one such group per view. | **(rec.)** Don't switch a tag to Primary to show it's chosen: `Selected` does that (below). | Uber: primary, actionable · Apple: a button that behaves like a toggle |
| **Secondary** | Uber: an actionable tag, with Primary (Spec). **(rec.)** The usual choice (rule 3 doesn't bind tags: [H5](../hierarchy.md)): tags in a search input, or a group of filters beside the content they filter, with `Color` as the category. | **(rec.)** Don't mix it with Primary in one group. | Uber: secondary, actionable · Apple: as Primary |
| **Tertiary** | Not in Uber for a tag people act on: Uber gives three levels to display tags only. The owner keeps it (ST1). **(rec.)** A quiet filter group, where a filled tag would compete with the content. | **(rec.)** Don't mix it with Primary or Secondary in one group. | Uber: none for selection · Apple: none |

#### Combinations

- **(rec.)** One `Hierarchy`, one `Color` and one `Size` across a group of selection tags. The chosen ones differ only by `Selected`, so the group reads as one control ([rule 2](../hierarchy.md) keeps one Size for buttons side by side).
- Display tags and selection tags may sit on the same screen; a selection tag isn't a Display tag that can be tapped.

#### States that carry meaning

- **Selected**: a 2 px ring in place of the 1 px rest ring, the fill unchanged (Ring). Apple asks that each state of a toggle look obviously different, not by colour alone (ST2).
- **Disabled**: Primary and Secondary take the same pale fill with no ring, as Uber Spec says ("the state has the same appearance for both hierarchies"). It's a control, so [rule 6](../hierarchy.md) applies: **(rec.)** say why next to it, such as a filter with no results.
- **Hover**: feedback only, never a Hierarchy change. Uber has Pressed instead (Known gaps).

#### Against the rules

| Rule in [hierarchy.md](../hierarchy.md) | Selection tag |
| --- | --- |
| 1. One Primary per context | Doesn't bind tags ([H5](../hierarchy.md)); **(rec.)** one Primary filter group per view, as [DT1](display-tag.md) |
| 2. Style, not size | Applies to a group **(rec.)** |
| 3. Secondary is the default | Doesn't bind tags ([H5](../hierarchy.md)); the default variant stays Primary: [DT2](display-tag.md) |
| 4. Tertiary is for ways out | Doesn't bind tags ([H5](../hierarchy.md)): dismissing a tag removes a filter, it isn't a way out of the screen |
| 5. Destructive is a `Type` | Doesn't apply: no `Type` axis, and a Red tag is a category (Uber Spec) |
| 6. Don't use Disabled to say something is missing | Applies |
