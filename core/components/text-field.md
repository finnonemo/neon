# Text field

> Core's Text field, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

```
Text field (variant root)          Fill × Hug, no fill, no padding, no min size (no Hit target)
└─ Container                       VERTICAL, Fill × Hug, gap 8 (raw)
   ├─ Label + Character count      HORIZONTAL, Fill × Hug, left aligned
   │  ├─ Title                     TEXT (hidden on Skeleton)
   │  └─ Skeleton title            120 × 16, radius 4 (Skeleton only)
   ├─ Field                        HORIZONTAL, Fill × Hug, min height Text field/Field/<Size>/Layout min-height, centred, padding 16 / 0, gap 16, radius 8, stroke 3 (Read-only 2), no clip
   │  ├─ Text overflow             Fill × Hug, padding 0 (hidden on Skeleton)
   │  │  ├─ Input text · Input Cursor · Placeholder text
   │  ├─ _Unit suffix              instance, shown by the `Unit` boolean; State pinned Enabled | Disabled
   │  └─ Status                    Incomplete · Warning · Complete glyph, or `_Loading`
   └─ Detail                       HORIZONTAL, gap 4 (raw), hidden on Skeleton
      └─ Helper Text | Error message | Success message | Warning message, with its glyph on Error / Success
```

No trailing action: Clear, its `Action slot` (#191) and `_Text field action` were removed 2026-11-02 (owner). Password field's eye is a plain Icons instance last in its `Field` ([password-field.md](password-field.md)).

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Text filled` | False · True | Input text or Placeholder text |
| `State` | Enabled · Pressed · Focus · Active · Error · Success · Incomplete · Warning · Complete · Read-only · Loading · Disabled · Skeleton | colours, stroke, the Status glyph, the Detail line |
| `Size` | Large · Medium · Small | Field min height 56 / 48 / 36, text styles, icon steps |

Properties: `Unit` (BOOLEAN, default False) shows `_Unit suffix`; linked in the 72 non-Skeleton variants. `Helper` (BOOLEAN, default True) hides the helper line with its `Detail` row; linked in the 54 variants where Detail holds only `Helper Text`, every State but Error, Success, Warning and Skeleton. Password field has no `Helper` (R4). 2 × 13 × 3 = **78 variants**.

Password is its own set, [Password field](password-field.md), since 2026-11-01: the `Input = Text | Password` axis the map gave it is gone (owner).

## Icon records

`Text field/Icon/<Step>/Type token = fa-sharp fa-solid/<Step>`. Beside text the step follows the input text (Icons): Large → Large (17), Medium and Small → Medium (15). The Status glyphs (and Password field's eye) take it; the Detail glyphs are Medium at every Size (beside Subheadline). `_Loading` is Medium (24) on Large, Small (20) otherwise.

## Text styles, wrapping and truncation

| Layer | Text style (Large · Medium · Small) | Lines | Text property |
| --- | --- | --- | --- |
| `Title` | `Headings/Headline` · `Body/Callout` · `Body/Subheadline` | wraps (auto height) | none yet |
| `Input text` | `Body/Body` · `Body/Callout` · `Body/Subheadline` | one line: Hug, auto width, `ENDING`, `maxLines` 1 (owner, 2026-11-02) | none yet |
| `Placeholder text` | as Input text | one line: Fill, auto height, `ENDING`, `maxLines` 1 (#191) | none yet |
| `_Unit suffix` › `Unit` | as Input text | one line, never cut | the Utility's `Unit` |

Height growth from #115's Thai line heights: 114 · 105 · 92 → **120 · 112 · 100** (Large · Medium · Small, measured on Active, Error and Loading variants, 2026-11-01).

## Hit target and Skeleton

- **Hit target**: none (owner, 2026-11-02, overturning ADR 0003 for this set; see its amendment). The Root hugs Container with no 48 floor, and there is no trailing action. Status glyphs are not targets. Password field keeps the Root target ([password-field.md](password-field.md)).
- **Skeleton**: `State=Skeleton`: the Field in `skeleton-element`, a 120 × 16 bar for the Title, no text, unit or Detail.

## Accessibility

- [x] 1. Each text / background pair passes in both modes: the contrast lint is clean (`check-specs.sh`, 2026-11-01). Value, placeholder and unit pass on `Field/field` over each Base surface.
- [x] 2. Meaningful non-text parts pass 3:1: the Focus / Active / Error / Success stroke, the Status and Detail glyphs. Incomplete and Complete glyphs use `text-negative` / `text-positive` because `icon-negative` (Dark 2.55:1) and `icon-positive` (Light 2.80:1) miss 3:1 on the Field (issues.md).
- [x] 3. The field is identified by more than its fill: the Title above, placeholder or value inside, stroke 2 on Focus, Active and Error (Filled fields).
- [x] 4. No state by colour alone: Error and Success carry a glyph and a message, Incomplete / Warning / Complete a glyph, Loading a spinner, Disabled the dimmed text, Read-only its outline.
- [x] 5. The Focus ring sits outside the Field: It is a 2 px `Focus/focus` stroke 4 outside the Field (a 2 px gap), radius 12 (8 + 4), around a filled `State=Enabled` field with Thai copy. `State=Focus` is editing, not keyboard focus.
- [x] 6. nothing clipped. The Field hugs its value above its min height. A long placeholder ends in "…" on one line. A long value no longer does in Figma: `Input text` is Hug, auto width since the owner's 2026-11-02 call, so it runs on past the Field (code still cuts it to one line).

- [x] 7. No text under 11 pt: the smallest is Subheadline.

## Usage

the other cases below are not drawn yet.

- The Title always shows; the placeholder is an example, not the label. Thai copy in every case.
- A password or other secret is a [Password field](password-field.md), not a Text field.
- Amounts: turn `Unit` on and set the unit on the `_Unit suffix` instance (Amount entry); the hero amount is Amount field.
- Read-only for a value the user can see but not change in a form; Disabled only for "can't interact".
