# Progress bar

> Core's Progress bar, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

As built in:

```
Progress bar (variant root)     Fill × Hug, no fill, no padding
└─ Container                    VERTICAL, gap 8 (Container/<Size>/Gap vertical); Inline: HORIZONTAL, centred, gap 16 (Container/<Size>/Gap horizontal); Fill × Hug
   ├─ Header                    HORIZONTAL, Fill × Hug (Inline: Hug), gap 8; Indent: padding left 16 (Header/<Size>/Padding left); shown by the Label boolean (on)
   │  ├─ Label                  text, Fill × Hug (Inline: Hug), wraps; TEXT property "Label text" = "Uploading…"
   │  ├─ Value                  text, Hug × Hug, one line; TEXT property "Value text" = "50%"; hidden at Indeterminate
   │  ├─ circle-check           Icons instance, Size Medium, Color support-success; Success only
   │  └─ circle-exclamation     Icons instance, Size Medium, Color support-error; Error only
   ├─ Track                     Fill × Fixed 2 · 4 · 8 by Size, radius 0, clip content, fill Layer/layer-03
   │  ├─ Indicator              ABSOLUTE, x 0, constraints horizontal SCALE, width a share of the Track, fill support-info · support-success · support-error by Status; hidden at 0% and Indeterminate
   │  └─ Segment                ABSOLUTE, SCALE, x 14%, width 72%, linear gradient Transparent → Support/support-info → Transparent; Indeterminate only
   └─ Message                   VERTICAL, Fill × Hug; Indent: padding left 16; hidden on Inline; linked to the Helper boolean on Active
      ├─ Helper text            Active; Text/text-helper; TEXT property "Helper text" = "2 of 4 files"
      ├─ Success text           Success; Text/text-helper; "Upload complete"
      └─ Error text             Error; Text/text-negative; "Upload failed. Try again."
```

- No `_` Items and no Slots. The two glyphs are Icons instances, as Text field's Detail glyphs.
- The Indicator's width is its Progress value's share of the Track: 0 · 0.25 · 0.5 · 0.75 · 1, written by the engine's `share` rule against the Track's laid-out width. `SCALE` keeps that share when an instance is resized, and a designer can drag it for an odd amount (40%) without detaching.
- The Segment is v2's 72% share, centred (Q18). Its stops bind `Transparent` at 0 and 1 and `support-info` at 0.5: a bound stop takes the variable's alpha too, so the ends can't be `support-info` at 0%.
- Pinned to the leading edge, so it mirrors in RTL in code.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Status` | Active · Success · Error | the Indicator's colour, the glyph, which message shows |
| `Progress` | 50% · 0% · 25% · 75% · 100% · Indeterminate | the Indicator's width (a share of the Track); hidden at 0%. Indeterminate shows the Segment and hides the Value |
| `Alignment` | Default · Inline · Indent | Inline: the Header beside the Track, no Message. Indent: the Header and the Message padded 16 |
| `Size` | Medium · Small · Large | the Track's and the Indicator's height, 4 · 2 · 8 |

Success and Error pair only with `Progress=100%` (an `exclude` rule). Panel order puts the default first; the grid's columns are `Size`, largest first, and its rows `Status` › `Alignment` › `Progress` ("Grid order" in Variant axes).

Properties: `Label` (BOOLEAN, on: shows Header), `Label text`, `Value text`, `Helper` (BOOLEAN, on: shows Message, linked on Active Default and Indent only), `Helper text`, `Success text`, `Error text` (TEXT; named apart from the booleans, as Banner's and Tile's `Title text`). 8 Status/Progress pairs × 3 Alignment × 3 Size = **72 variants**.

## Component variables and Theme tokens

`Components`, Tag's three-level shape. Container, Header, Track and Indicator are keyed by `Size` (they were keyed by `Progress`); the texts go under `Label`, keyed by role, as Toggle's `Title` / `Value` (structure.md).

| Group | Keyed by | Properties | Values (Small · Medium · Large) |
| --- | --- | --- | --- |
| `Progress bar/Container` | `Size` | Gap vertical, Gap horizontal (Inline) | `spacing-03` (8); `spacing-05` (16) |
| `Progress bar/Header` | `Size` | Gap horizontal, Padding left (Indent) | `spacing-03` (8); `spacing-05` (16) |
| `Progress bar/Track` | `Size` | Layout height, Radius | `spacing-01` · `spacing-02` · `spacing-03` (2 · 4 · 8); `None (radius-0)` |
| `Progress bar/Indicator` | `Size` | Layout height, Radius | the Track's |
| `Progress bar/Label` | role: `Label` · `Value` · `Helper` · `Success` · `Error` | Type token, Type emphasis, Align horizontal, Align vertical, Decoration | `$subhead`, `Regular`, `Left` (Value `Right`), `Top`, `-` |
| `Progress bar/Icon` | `Medium` | Type token | the glyphs' size |

4 groups × 3 sizes × 2 = 24 FLOAT, 5 roles × 5 + 1 = 26 STRING: **50 `Components` variables**.

- The Indicator's width is the set's **one unbound number**: a variable would fix it, and it would stop scaling with the Track. The spec writes it as a literal `width` rule with `share`, so the engine sets it against the Track's width.
- `Header` and `Indicator` are new group words (Q5).

Templates: `Components/Progress bar/<Group>/{{Size=*}}/<Property>`, `Components/Progress bar/Label/<role>/<Property>`.

`Theme`: no Component-scoped token; `Status` picks Theme tokens directly through rules (ADR 0001,). Measured 2026-11-04 with `skills/build-component/scripts/contrast.mjs` on the Theme snapshot.

| Theme token | Light | Dark | Paired with |
| --- | --- | --- | --- |
| `Support/support-info` (Indicator) | 7.33–8.16 on the track over each Base surface; 8.10–9.07 on the surfaces | 3.51 on the track; 5.12–7.10 on the surfaces | `non-text`, on `Track` |
| `Layer/layer-03` (Track) | 1.10–1.23 on the surfaces (1.23 on white; `Navy/10` since 2026-11-11) | 1.46–2.03 | exception: no track token reaches 3:1 (owner-approved in the spec); the fill and the Value text carry the meaning |
| `Text/text-primary` (Label) | 13.87–15.13 | 15.13–21.00 | `text`, on the Base surfaces |
| `Text/text-secondary` (Value) | 6.73–7.00 | 7.22–8.63 | `text`, on the Base surfaces |

The Status colours and the message texts are measured in 's Status colours table. The Segment's stops are `Transparent` and `support-info`: the static frame of a loop, measured as the Indicator.

Carbon binds the fill to `border-interactive` and the track to `border-subtle-01`. Core's `Border/border-interactive` isn't Carbon's blue: it is 1.26 on `layer-03` in Light and 1.35 in Dark, and 1.21–1.37 on the surfaces, so it can't carry the fill. `Border/border-subtle` is a decorative hairline (1.12 / 1.58 on `layer-01`). Hence the spec's `support-info` and `layer-03` (Q4). `Miscellaneous/interactive` was rejected in the spec: 4.46 in Light against `border-interactive`, and it means "tap me".

## Text styles, wrapping and truncation

| Layer | Text style | Lines | Text property |
| --- | --- | --- | --- |
| `Label` | `Body/Subheadline` (15/24, Regular), `Text/text-primary` | wraps; never truncated | `Label text` |
| `Value` | `Body/Subheadline` (15/24, Regular), `Text/text-secondary` | one line, Hug; a figure never truncates | `Value text` |
| `Helper text` · `Success text` · `Error text` | `Body/Subheadline` (15/24, Regular), `Text/text-helper` (Error: `Text/text-negative`) | wraps; never truncated | `Helper text` · `Success text` · `Error text` |

- The Value is one text property, so every variant shows "50%": the designer types the Value to match the Progress they pick, or "3 of 5", "฿12,000 / ฿20,000".
- Thai floors met: 15 where it wraps. Whether Label is a Label block title (17/24) is Q6.

## Hit target and Skeleton

- **Hit target**: None: not interactive. A tappable Tile or row around it is its host's target.
- **Skeleton**: None: no `State = Skeleton`. A host that loads in place (Tile, List item) draws its own Skeleton.

## Accessibility

- [ ] 1. Label `text-primary` and Value `text-secondary` pass 4.5:1 on all four Base surfaces in both modes (table above).
- [ ] 2. The Indicator `support-info` passes 3:1 on the track and on the surfaces in both modes (Dark 3.51 on the track is the lowest). The track is the stated exception.
- [x] 3. N/A: not a field.
- [ ] 4. Colour is never the only signal (revision 2): Success and Error each add a glyph and a message, and every pair a Status variant shows passes ('s Status colours table). The amount is in the Value text, on by default, as well as in the fill.
- [x] 5. N/A: not interactive.
- [ ] 6. In code, at AX sizes the Value may stack under the Label, and Inline may fall back to Default.
- [ ] 7. Smallest text 15 (Subheadline).
- [ ] 8. Motion: `moderate-01 · standard`, instant under Reduce Motion; Indeterminate `slow-01 · standard`, still under Reduce Motion; haptic None.
- [ ] 9. Role, name, states and focus order:

|  | Web |
| --- | --- |
| Role | `role="progressbar"` with `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow` |
| Accessible name | `aria-labelledby` the Label, or `aria-label` |
| Announced states | same |
| Focus order | same |
| Indeterminate | `role="progressbar"` with no `aria-valuenow` |

Behaviour rules for developers: values outside 0–1 are clamped; the fill starts at the leading edge; no haptic.

## Usage

The `Usage` frame shows, with Thai copy:

- Every Progress value, Label on.
- A custom Value ("฿12,000 / ฿20,000") under a savings-goal label, and "3 จาก 5" for a count.
- A long Thai label that wraps beside the Value.
- The bar with `Label` off, inside a Tile under the Tile's title.
- Indeterminate under a section's label, while its content loads.
- Don'ts: no Progress bar inside a control (a Button's wait is `_Loading`); no Indeterminate for a short wait on a surface (Progress circle); no Indeterminate where a Skeleton can show the shape to come; no Progress bar for named steps (Progress steps).

No Focus ring and no `iOS` pair.
