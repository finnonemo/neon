# Message card

> Core's Message card, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

Uber's two layouts in one tree, with Tile's Container, Active fill and Focus ring:

```
Message card (variant root)      Fill × Hug, no fill, no padding; min width and min height Interactive/Medium (48)
├─ Container                     VERTICAL, Fill × Hug, gap 0, radius 16, no clip; fill 0 by Style, fill 1 Transparent
│  │                             (Active: the pressed overlay); stroke 2 inside, out of layout: border-subtle on White
│  │                             and Light, none on Dark; Theme mode Light on Style Light and Dark (MC2)
│  ├─ Artwork top                Artwork=Top: Fill × 132; top corners round at the Container radius; image fill
│  │                             FILL, fill 1 Transparent (Skeleton: skeleton-background)
│  ├─ Body                       HORIZONTAL, Fill × Hug, gap 8, stretch
│  │  ├─ Content                 VERTICAL, Fill × Hug; padding top and bottom 16, left 0, right 16 (Top) or 0
│  │  │  │                       (Trailing); gap 0 (the space above the button is Actions' top padding)
│  │  │  ├─ Text                 VERTICAL, Fill × Hug, padding left 16, gap 0; hidden in Skeleton
│  │  │  │  ├─ Heading           Headings/Title 3, Type Emphasis Strong (20/28 Bold), wraps
│  │  │  │  └─ Paragraph         Body/Subheadline, wraps; hidden on Layout=Headline
│  │  │  ├─ Skeleton             Skeleton only: VERTICAL, Fill × Hug, padding left 16, gap 8, padding top and bottom 8
│  │  │  │  ├─ Heading line      160 × 8, skeleton-background
│  │  │  │  └─ Paragraph line    Fill × 8, skeleton-background; hidden on Layout=Headline
│  │  │  └─ Actions              HORIZONTAL, Hug × Hug; padding left 0 (tertiary) or 16 (secondary), top 4
│  │  │     │                    (tertiary) or 12 (secondary); hidden on Sub layout=Button none
│  │  │     └─ Button            Button, Size Small, Hug; Hierarchy and Type by Sub layout and Style (Hierarchy below);
│  │  │                          Trailing Icon on (`arrow-right`) for tertiary; iOS from the card's; State Enabled
│  │  │                          (Skeleton: Skeleton)
│  │  └─ Artwork trailing        Artwork=Trailing: 112 × Fill; right corners round at the Container radius; image
│  │                             fill FILL, fill 1 as Artwork top
│  └─ Dismiss                    Icon button Small, `xmark`, Secondary Default; absolute top right in the Container
│                                (its 48 Root flush with the card's corner), so it takes the Container's pinned Theme
│                                mode (MC2); iOS from the card's; BOOLEAN `Dismiss`, off; State Enabled (Skeleton:
│                                Skeleton)
└─ Focus ring                    State=Focus only: absolute at −4 on every side, stroke 2 inside Focus/focus,
                                 radius 20, no fill
```

- `Content`'s left padding is 0 and `Text`, `Skeleton` and `Actions` carry their own, so a Tertiary button's label (16 inside its own Container) lines up with the heading at 16, Uber's alignment, while a Secondary pill sits 16 in (MC5).
- `Text` holds the heading and paragraph at gap 0. It is not a Label block and the spec declares no `labelBlock`: lint's title role is a Headline over a `text-secondary` description with an 80 bar, where the card's is Title 3 over a `text-primary` paragraph (Uber's) with a 160 bar. Uber's 4 spacer is taken up by our Thai line heights (Subheadline 15/24 against Uber's 14/20).
- The Dismiss sits over the artwork in both layouts: top right of `Artwork top`, or of `Artwork trailing`. It never covers text, so `Content` keeps no room for it.
- No `_` Items, no Slots. Nested public instances: Button and Icon button, in every variant, hidden by `Sub layout` and `Dismiss`.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Layout` | Headline + paragraph · Headline | `Paragraph` and `Paragraph line` |
| `Sub layout` | Button tertiary · Button secondary · Button none | `Actions`, the Button's Hierarchy, `Content`'s gap and `Actions`' padding. Uber's "Button pill" is `Button secondary`, the Hierarchy it draws (MC4) |
| `Style` | White · Light · Dark | Container fill, stroke, Theme mode, text and Button colours (MC1, MC2) |
| `Artwork` | Trailing · Top | which artwork frame shows, `Content`'s right padding. Uber's values without the word "Artwork" |
| `State` | Enabled · Active · Focus · Skeleton | Active: the Container's second fill; Focus: the `Focus ring`; Skeleton: the bars, the artwork's skeleton fill, the nested controls' own Skeleton, and every Style drawn as White (Uber's Loading) |

Properties: TEXT `Heading text`, `Paragraph text`; BOOLEAN `Dismiss` (off). The button's label is the nested Button's own `Label Text`; the artwork is an image fill, changed by the designer, not an instance swap.

2 × 3 × 3 × 2 × 4 × 2 = **288 variants**, none excluded: the Dismiss shows in every variant, so `iOS` pins something in each.

Grid (Grid order): columns `Artwork`, then `iOS` innermost; rows `Style`, `Sub layout`, `Layout`, `State` innermost.

## Hit target and Skeleton

- **Hit target**: `Interactive/Medium` (48) min width and height on the Root in every variant. The smallest card (Headline, no button, Trailing) is 60 tall, so the binding never grows it. The whole card is one target (Uber); the nested Button is display only, hidden from assistive tech, as Tile's nested controls. The Dismiss is a second target with its own 48 Root.
- **Skeleton**: `State=Skeleton` (Uber's Loading). `Text` hides and `Skeleton` shows its bars; the artwork takes `skeleton-background` over the image; the Button and Dismiss take their own `State=Skeleton`; every Style draws White's fill and stroke, with the Theme mode not pinned.

## Usage

Samples in Thai, both Theme modes, on `background-secondary`:

- An upsell, `Style=Dark`, `Artwork=Trailing`, `Sub layout=Button secondary`: `เริ่มลงทุนกองทุนแรก` / `เปิดบัญชีวันนี้ รับส่วนลดค่าธรรมเนียม 50%` / `เปิดบัญชี`, with `Dismiss`.
- A nudge, `Style=Light`, `Sub layout=Button tertiary`: `ตั้งเป้าหมายการลงทุน` / `วางแผนเกษียณได้ในไม่กี่ขั้นตอน` / `เริ่มเลย`.
- A feature card, `Style=White`, `Artwork=Top`, `Layout=Headline`, `Sub layout=Button none`: `รู้จักกองทุนลดหย่อนภาษี`.
- Skeleton cards, Top and Trailing; `State=Focus` once.
- A Don't: a status message ("ชำระเงินไม่สำเร็จ") as a Message card; use a Contextual banner.

Where it goes: in a feed or under a section heading, full width with the screen's 16 inset; several in a row are a Carousel (pawisssh/design-system#665), all the same `Artwork`, 16 apart. Not for system messages (Banner / Contextual banner), brief feedback (Snackbar), or holding content (Tile).
