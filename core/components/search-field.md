# Search field

> Core's Search field, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

Text field's tree, with the magnifier first in `Field`, a single Helper line in `Detail`, and a `Status` frame that holds Clear or `_Loading`. The layer names match Text field's, so the generators read alike.

```
Search field (variant root)        Fill × Hug, no fill, no padding; min W / H Interactive/<Size> (call 2), Container centred
└─ Container                       VERTICAL, Fill × Hug, gap 8 (raw, as Text field)
   ├─ Label + Character count      HORIZONTAL, Fill × Hug; shown by `Label` (no character count)
   │  └─ Title                     TEXT
   ├─ Field                        HORIZONTAL, Fill × Hug, min height Search field/Field/<Size>/Layout min-height, centred,
   │  │                            padding 16 / 0, gap 16, radius (call 4), stroke 3 on Focus / Active (call 3), no clip
   │  ├─ Text overflow             Fill × Hug, padding 0 (hidden on Skeleton)
   │  │  ├─ Input text · Input Cursor · Placeholder text
   │  └─ Status                    Clear (Icons `circle-xmark`) or `_Loading`; hidden when neither shows
   └─ Detail                       HORIZONTAL, gap 4 (raw); shown by `Helper text`
      └─ Helper Text               TEXT
```

- `Input Cursor` pins the same `Class` as Text field's (`Body`, 24 tall, at every Size, read 2026-11-02) and shows only on `State=Active`. The Utility has no `Callout` class, so Medium's cursor isn't matched to Callout; Text field has the same gap.
- No `_` Item and no Slot. Clear is a plain Icons glyph, like Password field's eye (call 2).

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Text filled` | False · True | Input text or Placeholder text; Clear while Active |
| `State` | Enabled · Pressed · Focus · Active · Loading · Disabled · Skeleton | colours, stroke, the cursor, Clear or the spinner |
| `Size` | Large · Medium · Small | Field min height 56 / 48 / 36, text styles, icon steps |

- Properties: `Label` (BOOLEAN, default False) shows `Label + Character count`. `Helper text` (BOOLEAN, default False) shows `Detail`. Both are linked in every variant; on Skeleton the Title and Helper Text are hidden by rule, so turning either on there shows nothing.
- Skeleton has no value, so `{{State=Skeleton}}{{Text filled=True}}` is excluded, as on Password field.
- 2 × 7 × 3 × 2 − 6 = **78 variants**.
- The issue names `Size`, `State` and `iOS`. `Text filled` is Text field's axis, kept so that both fields read alike: call 1.
- No Error, Success, Incomplete, Warning, Complete or Read-only. No reference has a validation state on search.

## Icon records

`Search field/Icon/<Step>/Type token = fa-sharp fa-solid/<Step>`. Beside text, the step follows the input text (Icons): Large → Large (17), Medium and Small → Medium (15), as on Text field.

- **Clear**: `circle-xmark`, the filled circle-x Base draws.
- **`_Loading`**: Medium (24) on Large, Small (20) otherwise, as Text field.
- `Status` holds either Clear or the spinner, never both, and is not fixed-width. Text overflow fills the rest, so the shift is only in what the placeholder can show.

## Hit target and Skeleton

- **Hit target**: on the Root, `Interactive/<Size>/Interactive min-height` (48 · 48 · 56), with Container centred, as on Password field (ADR 0003). A tap anywhere focuses the field. Clear is a glyph inside it and has no target of its own: call 2.
- **Skeleton**: `State=Skeleton`, the same in both looks. The Field is filled `Skeleton/skeleton-background` with no glyphs and no text. `Label` and `Helper text` are hidden, so there is no Skeleton title bar (Carbon's Search Skeleton is the box alone).

## Usage

- Both looks side by side, with Thai copy: Enabled empty, and Active with a value, the cursor and Clear.
- The Focus ring once, on `iOS=False`.
- Built: Light and Dark columns at Medium.
- Search at the top of a list or a screen. The magnifier is the label, so `Label` stays off unless the search sits in a form.
- Not for entering a value that is then validated: that's a [Text field](text-field.md). Not for picking from a fixed list: that's Select.
- Cancel (iOS) and Back (Android) belong to the screen's toolbar or header, beside the field, not in it (call 6).
