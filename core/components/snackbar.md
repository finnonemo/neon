# Snackbar

> Core's Snackbar, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

The layer names are Carbon's Inline notification's where it has one (`Icon`, `Text`, `Action`, `Close`), and Uber's `Leading` frame.

```
Snackbar (variant root)        Fill × Hug, no fill, no padding, VERTICAL
└─ Container                   HORIZONTAL, Fill × Hug, min height 56, padding 0 · R · 0 · 16 (R by Action), gap 8,
   │                           radius 16, fill background-inverse, Floating shadow, items centred
   ├─ Leading                  Hug × Hug, padding 16 · 8 · 16 · 0, aligned to the top; hidden at Leading=None
   │  └─ Icon box              Fixed 24 × 24, centred
   │     ├─ Icon (TEXT)        status glyph; shown at Leading=Icon
   │     └─ _Loading           _Loading, Size=Medium (24); shown at Leading=Loading
   ├─ Text                     VERTICAL, Fill × Hug, padding 16 · 0, gap 0
   │  └─ Description (TEXT)    Body/Callout, wraps, no line limit; `Description text`
   ├─ Action                   Button: Hierarchy=Tertiary, Type=Inverse (Q9), Size=Medium, State=Enabled, no icons,
   │                           iOS={{iOS=*}}; `Label Text` exposed; shown at Action=Button
   └─ Close                    Icon button: Hierarchy=Tertiary, Type=Inverse (Q9), Size=Medium, State=Enabled, `xmark`,
                               iOS={{iOS=*}}; shown at Action=Button
```

- **Height**: 16 + 24 + 16 = 56 for one line, Uber's. The 48 Button and Icon button sit inside it. Copy that wraps grows the Snackbar 24 a line.
- **Right padding**: 16 at Action=None, 4 next to the buttons, Uber's.
- **Gaps**: The button's own 48 box supplies the inset, as Icon button does on In-line banner.
- **Top-aligned leading**: on a wrapped message the icon stays by the first line, as Carbon's does. The buttons stay centred.
- **Shadow**: the effect is the map's raw values until an `Elevation/Floating` style exists (Calls).

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Leading` | Icon · None · Loading | which of `Icon`, `Loading` or nothing shows (Q2) |

- **Sparse**: Leading=Icon takes all four Statuses; None and Loading take Info only, since nothing on the surface shows a Status there. As Button's Brand cells, the other combinations are not built.
- **Count**: 36 before).
- **Properties**: TEXT `Description text` ("Message"); the Button's `Label Text` ("Undo") reaches the set as the nested instance's exposed property. The glyph is the `Icon` layer's text, as List item's leading icon, so `Failure` and `Deleted` are a glyph change, not a Status (Q2).
- **Grid order**: rows by `Leading` × `Status` (Icon Info … Icon Error, None, Loading), columns `Action` × `iOS`, False before True in each pair (Grid order).

## Icon records

- **Status glyph**: `Snackbar/Icon/Medium/Type token = fa-sharp fa-solid/Medium`. It sits beside Callout (16), which has no step of its own and takes the next one down, Medium (Icons).
  - By Status: Info `circle-info`, Success `circle-check`, Warning `triangle-exclamation`, Error `circle-exclamation` (v2 Snackbar's glyphs).
  - Colour `icon-inverse` for every Status: the glyph tells them apart.
  - Other glyphs are the designer's text, e.g. v2's `circle-xmark` (Failure) or `trash-can` (Deleted), keeping the Status that sets the announcement.
- **Icon box**: fixed 24 × 24, so the glyph and the 24 `_Loading` swap without moving the text. This is #109's fixed-width rule where glyphs swap.
- **Close**: the Icon button's own record (`xmark`, Medium, `fa-sharp fa-solid/Large`).

## Hit target and Skeleton

- **Hit target**: the nested Button and Icon button bring their own 48 on their Root (ADR 0003). The Snackbar body is not a target; a tap on it does nothing. #109's "Hit target inside a box under 48": N/A, the Container is 56.
- **Skeleton**: none. Feedback appears on an event (Visuals).

## Motion

| Transition | Token | Reduced form | Haptic |
| --- | --- | --- | --- |
| Enters: slides up and fades in | `moderate-02 · entrance · slide-full` | crossfade | None |
| Leaves: slides down and fades out | `moderate-01 · exit · slide-full` | crossfade | None |
| A Loading Snackbar's outcome replaces it | the old leaves, the new enters | crossfade | None |
| The next Snackbar in the queue | enters after the current one has left | crossfade | None |

- **Haptic**: none on appearing. An outcome's `Success` or `Error` haptic is the Pattern's.
- **Movement**: `slide-full`, the Snackbar's own height up from the bottom edge, with its fade. Movement from Motion and haptics, the owner's D6 (ads-tokens.md § 5), edited in place at the owner's word ("Edit directly", #811, 2026-11-11).
- **Direction**: from the bottom edge, where a Pattern places it (Usage):
- Core's motion is Carbon's six durations and productive easings, the longest `slow-02`, 700 ms (Motion). On iOS `moderate-02` stands for a `.smooth` spring.

| Action | Leaves | Who can keep it |
| --- | --- | --- |
| None | after 3 s for one line, 5 s for two, 7 s for three or more (Uber's), or on a swipe | the timer pauses while the Snackbar is hovered |
| Button | never on a timer: on the action, on Close or on a swipe | the user |

- **Error**: an Error Snackbar takes Action=Button, never None (Usage).
- **Assistive tech**: while a screen reader is on, Action=None lengthens to the platform's recommended timeout (Android `getRecommendedTimeoutMillis`; iOS and web, 10 s).

## Usage

- **Placement**: A Pattern places it; the placement isn't an axis.
- **Use it** only after a user action, for feedback, an acknowledgement or a follow-up (Uber).
  - It sits over the content and follows the user forward and back through navigation.
  - One at a time: the next waits until the current one leaves. A Loading Snackbar is the one that is replaced, by its outcome, as soon as it lands.
  - It leaves on a swipe (phone), its action, Close or its timer.
  - Brief: one or two lines.
  - Specific: name what the user just did. "ทำรายการไม่ได้" names nothing; "ส่งคำสั่งซื้อไม่สำเร็จ" does.
  - Declarative: it reports what happened. Never a question.
  - A phrase or sentences: "กำลังบันทึกแผน" is enough when the screen gives the context.
  - No end punctuation: Thai has no full stop, so a message never ends in `.`, and two sentences are split by a space. Uber's full stops on two or more sentences apply to English copy only.
  - No exclamation mark, no `?`.
  - The action label: one or two words, a verb ("เลิกทำ", "ลองอีกครั้ง", "ดูรายการ", "ยกเลิก").
  - `Status=Success, Action=None`: `ยกเลิกคำแนะนำจากที่ปรึกษาแล้ว`.
  - `Status=Error, Action=Button`: `ส่งคำสั่งซื้อไม่สำเร็จ`, action `ลองอีกครั้ง`.
  - `Leading=None, Action=Button`: `ยกเลิกคำสั่งซื้อแล้ว`, action `เลิกทำ`.
  - `Status=Info, Action=Button`: `เพิ่มกองทุนในรายการโปรดแล้ว`, action `ดูรายการ`.
  - `Leading=Loading, Action=Button`: `กำลังส่งคำสั่งซื้อ`, action `ยกเลิก`, replaced by `ส่งคำสั่งซื้อแล้ว` (Success) when it lands.
  - Port's `มี 2 แผนที่มีคำแนะนำจากที่ปรึกษา` is not a Snackbar: no user action prompts it. It is an In-line banner or a Contextual banner.
- **Both looks**:
- **Focus ring**: shown once, on the Close of an `iOS=False` Button Snackbar.
- Success with no action, Error with `ลองอีกครั้ง`, the same on `iOS=False`, Undo (`Leading=None`, `เลิกทำ`), `ดูรายการ`, Loading with `ยกเลิก` above its Success outcome, and Close in Focus on `iOS=False`; the Don'ts listed under them, with the Error one added 2026-11-06. The samples set only component properties and text (`usage-overrides.js`: no gaps). A Thai message carries zero-width spaces between words (`เพิ่ม​กองทุน​ใน​รายการโปรด​แล้ว`), since Figma breaks unspaced Thai at any letter.
- **Don't**:
  - Stack Snackbars. The next one waits until the current one leaves.
  - Show one the user didn't cause: not system-prompted, not engagement or promotion ("ลองฟีเจอร์ใหม่"), not critical or emergency messages. Those are a banner or a Dialog: a timed message can't carry what a user must read.
  - Colour it by Status. It stays grey; colour is a banner's.
  - Leave an Error Snackbar without an action: Error always carries a Button ("ลองอีกครั้ง").
  - Give it a text button that only closes ("ปิด", "ตกลง").
  - Use a Primary or Secondary Button: Tertiary only, for passive feedback.
  - Put the only path to a task in its action. The action is a shortcut ("Undo", "ดูรายการ"), and the screen keeps the way to it.
  - Use one for an error the user must fix in a form: that's Text field's error or an In-line banner.
  - Use one for something that stays true on the page: that's a Contextual banner or an In-line banner.
  - Give it a title, two actions or a long paragraph.
  - Fire a haptic from the Snackbar itself.
