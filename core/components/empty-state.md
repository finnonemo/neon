# Empty state

> Core's Empty state, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

Carbon's tree (illustration, a heading-and-description frame, the action), with Base's numbers. Large is the first build unchanged.

```
Empty state (variant root)      Fill × Hug, no fill, no padding, not interactive; VERTICAL
└─ Container                    Fill × Hug, children centred on the cross axis
   │                            Large: VERTICAL, padding 36 (raw, Q3), gap 12 (spacing-04)
   │                            Medium: VERTICAL, padding 24 (spacing-06), gap 12 (spacing-04)
   │                            Small: HORIZONTAL, padding 16 (spacing-05), gap 12 (spacing-04)
   ├─ Artwork                   _Empty state artwork instance, Hug × Hug, Size={{Size=*}}; shown by `Artwork`; exposed for
   │                            its `Artwork text` (R5 (a)): 5XLarge 60/80 · 4XLarge 48/64 · 3XLarge 34/40, Icon/icon-primary
   ├─ Heading + Description     VERTICAL, Fill × Hug, gap 12 (Large, spacing-04) or 8 (Medium and Small, spacing-03)
   │  ├─ Title                  TEXT, Type Emphasis Strong, Text/text-primary, Fill × Hug; Large Headings/Title 3, centred;
   │  │                         Medium Headings/Headline, centred; Small Headings/Headline, left-aligned
   │  └─ Description            TEXT, Text/text-primary, Fill × Hug, centred; Large Body/Callout, Medium Body/Subheadline;
   │                            hidden on Small
   └─ Button                    Button instance, Hug × Hug: Hierarchy=Secondary, Type=Default, Size=Small, State=Enabled,
                                Leading Icon off, {{iOS=*}}; shown by `Button`; exposed for `Label Text` (Q5); hidden on Small

_Empty state artwork (part)     Hug × Hug, Size Large · Medium · Small, private (in the page's Items frame)
└─ Container
   └─ Artwork                   TEXT, Font Awesome ligature from `Artwork text` (circle-question), fa-sharp fa-solid/<step>,
                                Icon/icon-primary
```

- The root fills the width it is given and hugs its content. It doesn't centre itself vertically: the Pattern or screen puts it in the middle of the empty region (Base: "centered in their container"), and sets any max width (ADR 0013).
- Not a Label block. A Label block names a control or a row; this title and description are the region's content. So the spec declares no `labelBlock`, and the description keeps Carbon's and Base's `text-primary` rather than a Label block's `text-secondary`.
- Base's spacing comes from padding-bottom on each part's frame. Here the frames have no padding and the gaps do the work, as in Carbon.
- Gaps: Base's are 16 under the badge and 12 between the rest. Here every gap is 12, and the artwork's 80 line height, 10 above and below a 60 glyph, gives about 22 between the glyph and the title (an assumption: Base's look puts 16 there).
- No Slot. One `_` Item, `_Empty state artwork` (R5 (a)), in the page's `Items` frame.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Size` | Large · Medium · Small | the region (R2): Large a page, Medium a sheet or a list's section, Small an inline row. Container layout, padding and gaps, the artwork's step, the text styles, and on Small the row with no description or Button |

Properties: `Artwork` (BOOLEAN, on), `Title text` (TEXT, "No orders yet"), `Description text` (TEXT, "When you buy your first fund, your orders will show here.", linked off Small), `Button` (BOOLEAN, on, linked off Small). The Artwork is exposed for its `Artwork text` (`circle-question`), the Button for its `Label Text` ("Browse funds"). 3 × 2 = **6 variants**, grid one row, columns `Size` (Large first) × `iOS` False, True.

`_Empty state artwork` has `Size` only (3 variants), pinned by the host. No `State` axis (no Skeleton, no Disabled), no `Artwork` axis under Q1's recommendation (R5 (b) not taken). The defaults are English (the owner's direction for group C); Thai copy goes in Usage.

## Icon records

- `Empty state/Icon/5XLarge/Type token = fa-sharp fa-solid/5XLarge` (60/80), `Empty state/Icon/4XLarge/Type token = fa-sharp fa-solid/4XLarge` (48/64) and `Empty state/Icon/3XLarge/Type token = fa-sharp fa-solid/3XLarge` (34/40), on the part's `Artwork` at Size Large, Medium and Small (R3, R4, R5 (a)). Standalone artwork, so no paired text style (Icons). The records keep Empty state's prefix, as `_Toggletip caret`'s keep Toggletip's.
- The glyph is a TEXT property (`Artwork text`), so a Pattern swaps it by typing a ligature: Those are the Patterns' picks, not this set's.
- The layer hugs its glyph. Glyph widths vary (`triangle-exclamation` runs wider than `circle-check`), but the layer is centred alone on its line, so a fixed width buys nothing.
- No Base two-tone badge: Font Awesome has no badge shapes, and hand-drawn vectors are banned (structure.md). Solid `circle-*` glyphs (`circle-check`, `circle-exclamation`, `circle-info`, `circle-question`, `circle-xmark`) carry their own disc;

| Layer | Text style | Lines | Text property |
| --- | --- | --- | --- |

| `Description` | Large `Body/Callout` 16/24; Medium `Body/Subheadline` 15/24; none on Small | wraps, no limit | `Description text` |
| `Button` › `Label` (nested) | Button Small's own | one line, never cut: a control label | the exposed Button's `Label Text` |

- Title: Base's Heading XSmall is 20/28 Bold and Carbon's `heading-03` is 20/28. Core's Title 3 is Regular, so it takes `Strong`, as [avatar.md](avatar.md) does at 48.
- Description: Base's Paragraph Medium is 16/24 (Carbon 16/22), which is Callout 16/24 here.
- Content text wraps with no line limit (Localisation). Base's "one-line headline" is copy guidance, not a `maxLines`. Thai that wraps is 13 or larger: both styles pass. Copy has no manual line breaks.
- Base's bigger headline and paragraph at 600 and 1136 aren't variants. Width doesn't make a variant (ADR 0013); a web Pattern at regular width can override the styles if it needs to.

## Hit target and Skeleton

- **Hit target**: None of its own. The Empty state isn't a control. The nested Button brings its own 48 (its Root's min width and height, `Interactive/Small`) around its 36 Container, so nothing overflows.
- **Skeleton**: None (the map). An Empty state shows only after the content has loaded and come back empty; until then the region shows its own Skeleton (GLOSSARY, Empty state).

## Usage

- **Use it** to fill a region that has nothing to show: a list with no rows yet ("ยังไม่มีรายการ"), a search with no results, a page the user can't open (403), a failed load (4xx, 5xx), Maintenance, or a feature's first use. Each case in a product is a Pattern component over one Empty state (`<Context> Empty state / <Case>`, #73), not a new variant.
- **Don't** use it while content loads (Skeleton), for feedback after an action (Snackbar), or beside content that is still there (a Contextual banner). An account's `MAINTENANCE` status card is a Contextual banner or a Tile Pattern, not this.
- **Placement**: centred in the empty region, both ways. On a phone it fills the width (36 in from each side); a web Pattern caps it (Base's 472 or 536).
- **Copy** (Base's Content guidance, in Thai): a short title that says why it's empty, not a question; one or two sentences on what will show and how; a Button only when there's a clear next step ("ซื้อกองทุน", "ลองใหม่", "กลับหน้าหลัก"). The 5xx page turns the Button off.
- Light and Dark columns of Thai samples, each with an English note: the Don'ts listed under them. The samples set only component properties and text (`usage-overrides.js`: no gaps).
