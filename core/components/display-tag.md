# Display tag

> Core's Display tag, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

```
Display tag (variant root)   Hug × Hug, no fill, no padding
└─ Container                 HORIZONTAL, Hug × Hug, min-height Display tag/Container/<Size>/Layout min-height; fill, radius, padding, gap bound
   ├─ Leading Icon           TEXT, fa-sharp fa-solid/<Size>; visible = BOOLEAN `Leading Icon`
   ├─ Label                  TEXT, one line, auto width
   └─ Trailing Icon          TEXT, fa-sharp fa-solid/<Size>; visible = BOOLEAN `Trailing Icon`
```

Tertiary has a stroke (`strokes[0]`, weight 1). Primary and Secondary have none.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Color` | White · Yellow · Navy · Light Grey · Green · Blue · Purple · Red · Orange · Indigo | the Theme token family |
| `Hierarchy` | Primary · Secondary · Tertiary | fill strength; Tertiary's outline |
| `State` | Enabled · Disabled | Disabled fill and `Text/text-disabled` label and icons |
| `Size` | Large · Medium · Small · XSmall | min-height, padding, gap, radius, text style, icon step |

Properties: BOOLEAN `Leading Icon` and `Trailing Icon`, on by default, as Button's (owner, 2026-11-09, after the CDS gap review). 10 × 3 × 2 × 4 = **240 variants**.

`Theme`: no new tokens. The set binds the existing `Tag/<Colour>/<Hierarchy>/<role>` component tokens, which the live Display Tag and Selection Tag also bind: Carbon's Tag has per-colour component tokens, and a new set reuses what is there rather than copying it (the owner's call, 2026-11-02). - Roles: `background`, `background-disabled` and `color`, plus `border` and `border-disabled` on Tertiary.
- The first build made 110 `Display tag/<Colour>/<Hierarchy>/<role>` copies; they were deleted the same day, once nothing bound them.

Matched to Uber Base's Tag on 2026-11-02 (Light; Uber has no Dark here), then evened out across colours the same day (the owner asked for the same tone and shade in every colour). At rest here: 6.45, 5.75 and 5.40:1 (was 5.40, 5.11 and 5.04) over `layer-02`, the lowest Base surface.

Kept, with why:
- **Yellow** stays a light chip: a `Yellow/100` fill with a `Yellow/185` label, a `Yellow/160` Secondary label and a `Yellow/185` Tertiary label (the nearest passing step). At L\* ~42, Yellow turns olive. Uber's amber `#f6bc2f` has no near step in our lemon Yellow.
- **White and Navy** are the neutral light and dark chips, so they are unchanged.
- **Blue** stays in our cyan Blue. Uber's royal blue is nearer Indigo, which is its own colour here.
- **Light Grey** is blue-grey. Neutral Grey has nothing between `/50`, which fails with white, and `/75`, which is far darker.
- **Secondary backgrounds** stay `/5`, and Tertiary borders stay `/15`.
- **`Purple/105`** is in `theme.json` but not in the Colors library.

Disabled label and icons bind `Text/text-disabled` directly.

Pairs (the spec's `contrast` list):
- Label (text) on the Container fill;
- each icon (non-text) on the Container fill;
- the fill and Tertiary's outline are decorative.

## Icon records

`Display tag/Icon/<Step>/Type token = fa-sharp fa-solid/<Step>`, one per Size (Large, Medium, Small, XSmall). Beside text the icon takes the label's step (Icons, ADR 0006). Glyphs are the live set's (a plus and a chevron). No fixed-width icon layer: designers swap the glyph text.

## Usage

- A status, category or attribute label (a fund's risk level, an order's state).
- Not tappable. For a choice someone taps, use Selection tag.
- Copy fits on one line at 375 wide in Thai.
- Which `Hierarchy` to pick: Hierarchy below.

### Hierarchy

How loud a tag's label is, not how important an action is, so Button's action rules don't carry over unless a source says so. The words, the rules every component keeps and the owner's calls are in [hierarchy.md](../hierarchy.md); under [H5](../hierarchy.md) (the owner, 2026-11-09) rules 1–4 bind actions only, so on a tag `Hierarchy` is visual emphasis. This section adds Display tag's own. Sources: Uber Base [Tag, Usage](https://base.uber.com/6d2425e9f/p/62e25d-tag/b/51ca36), [Content](https://base.uber.com/6d2425e9f/p/62e25d-tag/b/940177) and [Spec](https://base.uber.com/6d2425e9f/p/62e25d-tag/b/89a6a8), Uber Base [Badge](https://base.uber.com/6d2425e9f/p/554ab6-badge), Apple HIG [Labels](https://developer.apple.com/design/human-interface-guidelines/labels), read 2026-11-09. A rule marked **(rec.)** is our recommendation, not a source's.

**Matched to Uber's Tag, Display tags.** Uber's Tag page names two types, "Display tags" and "Selection tags": our two sets. It calls Display tags "text tags" in its Hierarchy part, and its word there is "hierarchy", not "Type" as on Button. Uber's Badge is a different component: a notification count or a dot, in five semantic colours, with no text label and no states. Apple has no tag component.

How each value looks, from the `Tag/<Colour>/<Hierarchy>/…` aliases in theme.json: Primary is a solid fill in the hue: dark with a white label, except White, Yellow and Navy, which keep a contrasting label in the hue; Secondary is a light tint with the label in the hue; Tertiary has no fill, a light outline, and the label in the hue.

| `Hierarchy` | Use for | Don't | Uber · Apple |
| --- | --- | --- | --- |
| **Primary** | A status or category that must be seen at a glance. Uber allows it for high-priority statuses (an order that failed) and for categories whose colours people already know (transit lines). At most one Primary tag per item (a row, a card), for its status; it doesn't count toward a screen's one Primary (DT1, decided). | Don't scatter Primary tags across a page: they compete, and when everything is highlighted, nothing is (Uber Usage, Do / Don't). | Uber: text tag, primary level · Apple: none |
| **Secondary** | Properties of an item, in a group of tags, with `Color` as the category: a fund's risk level, its asset class (Uber Do: "secondary and tertiary tags for groups of tags that highlight the properties of an item"). **(rec.)** The usual choice for a property tag, from Uber's Do; rule 3 doesn't bind tags ([H5](../hierarchy.md)). | Don't pick a colour to mean danger or success: tag colours are primitives with no semantic meaning (Uber Spec). The label carries the meaning (Accessibility item 4). | Uber: secondary level · Apple: none |
| **Tertiary** | The quietest label: neutral metadata beside Secondary tags. Uber puts it with Secondary for property groups and doesn't say how the two differ. **(rec.)** Tertiary for neutral metadata, often Light Grey, as in the "Fund attributes" sample on the Tags page. | Not a way out ([rule 4](../hierarchy.md) doesn't bind tags: [H5](../hierarchy.md)). Not a dimmed or unavailable look: that's Display tag `State=Disabled` (DT3). | Uber: tertiary level · Apple: none. Apple's `tertiaryLabel` is "text that describes an unavailable item", which is our Disabled, not this. |

**Label**, on every value (Uber Content): 1–2 words, one line; nouns, noun phrases, product names, adjectives, places, distances and times ("7 min walk", "1.3 mi"); no verbs. For tags derived from data, adjectives such as "Recommended" or "Trending up".

#### Combinations

- **A group of property tags**: Secondary and Tertiary, side by side (Uber Do). **(rec.)** One `Size` across the group, as [rule 2](../hierarchy.md) asks of buttons.
- **A status with properties**: one Primary for the status, Secondary and Tertiary for the rest **(rec.)**.
- **How many**: Uber gives no number. Too many tags on a screen raise the cognitive load, and Uber suggests a governance process for tags on prominent surfaces, covering limits and static vs interactive tags (Content).
- Tags in a cluster wrap to the next row on a narrow screen; a single tag never wraps (Uber Usage).

#### States that carry meaning

- **Disabled**: Primary and Secondary take the same pale fill, and Tertiary keeps its outline; every label is `Text/text-disabled`. This matches Uber Spec ("When they are disabled the state has the same appearance for both hierarchies"). Uber gives Disabled only to tags people can act on; this one keeps it only to show that the item it describes is unavailable, with words that say so (DT3, decided).
- No Hover, Pressed or Focus: not interactive (Hit target).

#### Against the rules

| Rule in [hierarchy.md](../hierarchy.md) | Display tag |
| --- | --- |
| 1. One Primary per context | Doesn't bind tags ([H5](../hierarchy.md)); a Primary tag doesn't count toward it. At most one Primary tag per item: DT1 |
| 2. Style, not size | Applies to a group of tags **(rec.)** |
| 3. Secondary is the default | Doesn't bind tags ([H5](../hierarchy.md)); the set's default variant stays Primary: DT2 |
| 4. Tertiary is for ways out | Doesn't bind tags ([H5](../hierarchy.md)): Tertiary is the quietest label |
| 5. Destructive is `Type=Danger` | Doesn't apply: no `Type` axis, and a Red tag is a category (Uber Spec) |
| 6. Don't use Disabled to say something is missing | For controls; a static tag's Disabled marks an unavailable item, with words that say so: DT3 |
