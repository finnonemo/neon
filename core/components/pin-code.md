# PIN code

> Core's PIN code, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

```
PIN code (variant root)              Hug × Hug, no fill, no padding; min 48 × 48 (Hit target)
└─ Container                         VERTICAL, Hug × Hug, gap 8 (raw, as Text field)
   ├─ Label + Status                 HORIZONTAL, Fill × Hug, gap 8
   │  ├─ Title                       TEXT, Fill (hidden on Skeleton)
   │  ├─ Skeleton title              120 × 16, radius 4 (Skeleton only)
   │  └─ Loading                     _Loading instance, Small (20), Loading only
   ├─ Field                          HORIZONTAL, Hug × Hug, gap 4: the row of cells
   │  └─ Cell 1 … Cell 6             _PIN cell instances, exposed; Content and State pinned per variant
   └─ Detail                         HORIZONTAL, Fill × Hug, gap 4 (raw), hidden on Skeleton
      └─ Helper Text | Error message | Success message, with its glyph on Error / Success

_PIN cell (Item root)                Hug × Hug, no fill
└─ Container                         the box: Hug, min 48 × 48, centred, radius 8, stroke 3, no clip
   ├─ Value                          TEXT: the digit, ● (Dot) or ○ (Empty)
   └─ Input cursor                   Utility instance, State=Active only (Value stays, empty, beside it)
```

- **`_PIN cell` is an Item.** A partly typed PIN has a different state in each cell: dots, then the current cell, then empty cells. Host axes can't express that. Exposed cells let a designer set each cell's `Content` and `State` on the instance.
- **Width comes from the cells.** The Root and Container hug the `Field` row (4 × 48 + 3 × 4 = **204**; 6 × 48 + 5 × 4 = **308**). Title and Detail fill that width and wrap inside it. The Pattern centres or start-aligns the whole thing.
- **Status sits in the label row, not in the box.** This follows Base, which puts its Complete check in the label row. A cell is too small for a glyph beside the digit, so Text field's in-Field `Status` doesn't carry over.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Length` | 6 · 4 | how many `Cell` instances show |
| `State` | Enabled · Pressed · Focus · Active · Error · Success · Loading · Disabled · Skeleton | each cell's pinned `State` and `Content`, the Detail line, `_Loading`, the Skeleton title |

No properties. 2 × 9 = **18 variants**. `_PIN cell`: `Content` (Empty · Dot · Digit) × `State` (Enabled · Pressed · Focus · Active · Error · Success · Disabled · Skeleton). Focus, Active and Skeleton come in `Empty` only, so the Item has 5 × 3 + 3 = **18 variants**.

What each host `State` pins on its cells (n = `Length`):

| Host `State` | Cells |
| --- | --- |
| Enabled | all `Empty · Enabled` |
| Pressed | all `Empty · Pressed` |
| Focus | cell 1 `Empty · Focus`; the rest `Empty · Enabled` |
| Active | cells 1–2 `Dot · Enabled`; cell 3 `Empty · Active` (cursor); the rest `Empty · Enabled` |
| Error, Success | all `Dot · Error` or `Dot · Success` |
| Loading | all `Dot · Enabled`; `_Loading` shows |
| Disabled | all `Empty · Disabled` |
| Skeleton | all `Empty · Skeleton` |

Grid (Grid order): columns `Length` (6, 4), rows `State`. The Item's grid is one column, `Content` then `State`: the Empty-only States leave a row short in any `Content` × `State` grid, which lint fails.

Pairs (the spec's `contrast` list): Title and the Detail lines on the Base surfaces. Value (digit, dot, ring) on each cell fill. The Detail glyphs on the surfaces (non-text). The Focus, Active, Error and Success strokes (non-text). The fill behind passing text (decorative). The Focus ring.

## Icon records

`PIN code/Icon/Medium/Type token = fa-sharp fa-solid/Medium`, for the Error and Success Detail glyphs beside Subheadline (as Text field's Detail glyphs: `circle-exclamation`, `circle-check`). `_Loading` is Small (20), beside the Title. No icon goes in a cell.

| Layer | Text style | Lines | Text property |
| --- | --- | --- | --- |
| `Title` | `Headings/Headline` (Text field Large's) | wraps inside the row's width | none yet (Text field's later change) |

Thai copy appears in Title and Detail only. Digits are Latin, so no Thai floor applies in the cells.

## Hit target and Skeleton

- **Hit target**: the whole PIN code is one target. The Root's min width and height bind `Interactive/Medium/Interactive min-height` (48), Container centred (ADR 0003), as Password field does. The Root is always larger than 48 (the Field row alone is 48 tall), so this never grows it. A cell is not a target: a tap anywhere focuses the one hidden input. Text field dropped its Root target on 2026-11-02; whether PIN code follows it is call 4.
- **Skeleton**: `State=Skeleton`. Every cell is `Empty · Skeleton` (a 48 box filled `skeleton-background`, no glyph). The Title becomes a 120 × 16 bar. No Detail.

## Accessibility

Items 1, 2 and 6 were checked on the built set on 2026-11-02. The rest are settled here.

- [x] 1. Text pairs pass in both modes: the contrast lint passes on both specs. Value and `○` use `text-primary` / `text-placeholder` on `Field/field` and `background-primary`, which Text field already passes (6.16:1 or more on the field).
- [x] 2. Non-text parts pass 3:1: the contrast lint passes. These are the Focus (`Focus/focus`), Active (`border-strong`), Error and Success strokes, and the Detail glyphs.
- [x] 3. Identified by more than its fill. The Title is above. Each empty cell shows `○` at placeholder contrast and each typed cell a `●`. The current cell has stroke 3 (Filled fields).
- [x] 4. No state by colour alone. Error and Success carry a glyph and a message. Loading has a spinner, Disabled dimmed text, and the current cell its cursor and stroke.
- [x] 5. The Focus ring sits outside the `Field` row. 2 px `Focus/focus`, 2 px gap, radius 12 around the row. `State=Focus` is editing, not keyboard focus, as in Text field.
- [x] 6. 6 Enabled, 4 Error and 6 Active per size, long Thai copy). The rows keep 308 and 204 wide and every cell stays 48 wide. Title and Detail wrap inside the row's width; nothing clips. Heights (6 Enabled / 4 Error / 6 Active): Thai below-base marks in the Detail sit 1, 2 and 5 px below Subheadline's line box at the three sizes: a Typography line-height matter Text field shares, not fixed here (Build log).
- [x] 7. No text under 11 pt: the smallest is Subheadline.
- [x] 8. The Motion part names each transition.
- [x] 9. Role, name, states and focus order: one control, one focus stop.

## Usage

- A short numeric secret or code entered digit by digit: a sign-in PIN (6, masked), a one-time code (6, digits shown, through each cell's `Content=Digit`). A 4-digit PIN is `Length=4`.
- The system number keyboard enters the digits. The Numpad is Out (Inventory), so no keypad is drawn under it.
- A password or an alphanumeric secret is a [Password field](password-field.md), not this.
- What happens after a wrong PIN belongs to the sign-in Pattern, as an outcome: clearing the cells, the `Error` haptic, a lockout message.
- Thai copy in the Title and Detail, e.g. `รหัส PIN`, `กรอกรหัส 6 หลัก`, `รหัส PIN ไม่ถูกต้อง`.
