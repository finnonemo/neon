# Sliding button

> Core's Sliding button, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

```
Sliding button (variant root)   Fill × Hug, no fill, no padding; min height Interactive/Large (56)
└─ Container                    HORIZONTAL, Fill × Hug, min height Container/Large Layout min-height (56), radius, clips;
   │                              fill Button/button-secondary (Disabled: same)
   ├─ Indicator                 ABSOLUTE, left 0, constraints SCALE × Stretch; HORIZONTAL, items end, Round-cornered like the Container,
   │  │                           min width = the Handle; width a share of the Container (Enabled · Disabled: the Handle only;
   │  │                           On drag 0.4; Complete · Loading 1.0); fill Button/button-primary (Disabled: Button/button-disabled)
   │  └─ Handle                 Fixed Thumb/Large Layout width (56) × Fill height, centred; holds the Arrow; hidden on Loading
   │     └─ Arrow               TEXT, `fa-sharp fa-solid/Large`, glyph `arrow-right` (S6); icon-on-color, Disabled icon-disabled
   ├─ Label                     HORIZONTAL frame, Fill × Hug, padding Label/<State> (72 each side: the text centres on the whole frame), centred; holds Text
   │  └─ Text                   TEXT "Slide to confirm", Body/Body, Fill, centred
   │                              the Label is above the Indicator in z-order so it stays readable on the fill; opacity 0 on On drag and Loading, not hidden (S3)
   └─ _Loading                  instance, State=Loading only, ABSOLUTE, centred, Size pinned Medium (24)
```

- No `_` Items and no Slots. The Arrow is a Font Awesome glyph in a TEXT layer (Button's icons), `_Loading` the Utility instance, as Button nests it.
- The Indicator's width is the share of the Container the user has dragged, Slider's rule: a designer drags it and the Handle follows its trailing edge. The five variants are five poses: at rest, held part-way, past the threshold (Complete), waiting on the host (Loading), and unavailable.
- Complete and Loading are both full: Complete is the pose at the threshold, with the label in white over the fill and the Arrow at the end; Loading is the same fill with the spinner and nothing else. In code the host starts Loading when the action begins.
- Pinned to the leading edge, it mirrors in RTL in code.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `State` | Enabled · On drag · Complete · Loading · Disabled | the Indicator's share, which parts show, the colours (lifecycle order: rest, held, reached, busy, unavailable) |

Properties: TEXT `Label text` ("Slide to confirm", English in the set; the Usage samples and Patterns set Thai, "เลื่อนเพื่อยืนยัน"; one default set-wide, so Complete shows the same words). 5 = **5 variants**. No `Size` (S1), no `Hierarchy` or `Type` (S9), no `Skeleton` (S10), no `iOS` (S2). The grid is one row.

## Icon records

`Sliding button/Icon/Large/Type token = fa-sharp fa-solid/Large`, the Arrow. Uber's `arrow_dot_right` and `arrow_right` aren't Font Awesome: one glyph, `arrow-right`, serves the Handle and Complete (S6). The Handle is a fixed 56 wide with the Arrow centred, so nothing moves if the glyph changes (Icons, ADR 0006).

## Text styles, wrapping and truncation

| Layer | Text style | Lines | Text property |
| --- | --- | --- | --- |
| `Label` | `Body/Body` (Button Large's) | wraps and is never cut: a control label (Localisation) | `Label text` |

Thai floor met: 17 is the smallest. Use "เลื่อน" for the gesture, never "ปัด" (swipe, Uber's rule). The sample copy is "เลื่อนเพื่อยืนยันการโอน".

## Hit target and Skeleton

- **Hit target**: `Interactive/Large` (56) as the Root's min height, Container centred (ADR 0003). The user drags the Handle, 56 × the Container's height, which is the target.
- **Skeleton**: None (S10): it is shown with the amount it confirms, never before it. Loading is the busy state.

## Motion

| Transition | Token | Reduced form | Haptic |
| --- | --- | --- | --- |
| The Indicator follows the finger | none: it tracks the drag | kept: the user's own movement | None while dragging |
| Passing the threshold: the Indicator runs to full, the label turns white (Complete) | `moderate-01 · standard` | instant | `Impact` once, at the threshold (a snap, not a drag, Motion and haptics) |
| Released short of the threshold: the Indicator returns | `moderate-01 · standard` | instant | None |
| Complete → Loading: the Arrow and Label swap for the spinner | `fast-02 · standard` | instant | None |
| Loading | `_Loading`'s loop | keeps turning | None |

The outcome (a transfer done or refused) fires `Success` or `Error` from the Pattern, never from this component (Haptics). The haptic is iOS and Android only, with the table's constants; web has none, and the component is not for web. This adds a Sliding button row to the per-component table, in this PR.

Behaviour rules for developers: the screen-reader and switch path is a plain press with no threshold; the slide's threshold is High (80%) by default and Low (20%) where the users may struggle (S5); a slide that ends short returns to Enabled; after Complete the host starts Loading and then the PIN code.

## Usage

- The five states in a row (one size, one look), Thai copy ("เลื่อนเพื่อยืนยันการโอน"), Light and Dark.
- The Focus ring once (Light and Dark).
- Where it sits: the last step of a flow, in the bottom dock where the Primary [Button](button.md) would be, full width. It counts as the screen's one Primary ([hierarchy.md](../hierarchy.md) rule 1).
- Not for: a routine action (a Button: Uber's "may add unnecessary complexity"), identity (PIN code), web (a Button), or a destructive-action warning (an Alert's confirm).
- A `### Hierarchy` section: N/A, there is no `Hierarchy` axis (S9).
