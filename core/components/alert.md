## Accessibility

- [x] 1. `Text/text-primary` on `Layer/layer-01`: 15.13:1 Light, 17.40:1 Dark. The Buttons' and Text fields' pairs are theirs, and pass their lint on `iOS=False` (Button's Accessibility item 1);
- [x] 2. No non-text part of its own; the fields' strokes are Text field's.
- [x] 3. The fields are Text field, identified by more than their fill.
- [x] 4. A destructive action is named by its label as well as red (`Type=Danger`); the alert's modal state is the system's or the web's, not the scrim's colour alone.
- [x] 5. The Focus ring is the Buttons' and Text fields' own, outside each (`iOS=False`); the alert itself takes no focus.
- [x] 6. **Reflows** since Button's . `reflow-check.js` (`84e87b06`, 2026-11-10, `Show Text Field` on, Thai copy, 343): `counts` {}; Title, Message, the fields and the Buttons' labels wrap and the alert grows: at large sizes use Stacked (iOS does it itself; elsewhere the Pattern picks it). The Text field's placeholder truncates with "…", the field's own behaviour.
- [x] 7. No text under 17.
- [x] 8. Motion names System and the `iOS=False` tokens, reduced forms and haptic.
- [x] 9. Role, name, states and order:

|  |  | Android (`iOS=False`) | Web (`iOS=False`) |
| --- | --- | --- | --- |

## Usage

- Page `Alerts` (new, between `Accordions` and `Amount fields`, from the `Templates` clone): the set in Components; no Items. A base in its set frame on 🚧 Drafts (Side-by-Side, both looks) waits for the owner before the set is built (`build-component` step 1).
- Samples in Light and Dark columns, Thai copy, over a screen with the `Miscellaneous/overlay` scrim:
  - Side-by-Side, both looks: "ออกจากระบบ?" (Log out?), "คุณต้องเข้าสู่ระบบอีกครั้งเพื่อดูพอร์ตของคุณ", Dismiss "ยกเลิก", Preferred "ออกจากระบบ" (logging out isn't destructive, [hierarchy.md](../hierarchy.md) rule 5).
  - Destructive confirmation: "ลบบัญชีธนาคารนี้?", Message on what is removed, Preferred `Type=Danger` "ลบบัญชี", Dismiss "เก็บไว้".
  - Stacked, three actions: "ยืนยันตัวตนไม่สำเร็จ" (Couldn't verify you), Preferred "ลองอีกครั้ง", Other "ใช้รหัส PIN", Dismiss "ยกเลิก".
  - With a field: "ตั้งชื่อพอร์ต", one Text field (`Second Field` off), "ยกเลิก" / "บันทึก".
  - Web at Regular width: `iOS=False` centred in a `Screen 1280` (Sheet's K8 (a): a confirmation is Alert there).
- Not for: a form, long content or several steps (Sheet; at Regular width `Sheet - iPad`); a choice among several actions from a control (Action Sheet, #151, or Menu); feedback that needs no answer (Snackbar, the banners).
- Two to three actions. Labels short: two that don't fit 84 each go Stacked.

### Hierarchy

Alert pins its Buttons' `Hierarchy`; the shared rules are in [hierarchy.md](../hierarchy.md). An alert is its own context, so its Preferred is the one Primary (rule 1).

| Button | Pinned | Use for | Apple role |
| --- | --- | --- | --- |
| `Preferred` | Primary, `Type=Default` | the answer the alert asks for: "บันทึก", "ออกจากระบบ" | Default (answers Return) |
| `Preferred`, destructive | Primary, `Type=Danger` (set on the instance) | the confirmation step of [Destructive flow](button.md): "ลบบัญชี" | Destructive, never the default |
| `Other` (Stacked) | Secondary | a related action that isn't a way out: "ใช้รหัส PIN" (H4). An Other that discards ("ไม่บันทึก", Apple's Don't Save) is destructive: `Type=Danger` on the instance (rule 5) | Normal (Destructive when it discards) |
| `Dismiss` | Tertiary | the way out: "ยกเลิก", "เก็บไว้" (rule 4; the opposite of the Preferred, button.md's Opposite actions) | Cancel |
