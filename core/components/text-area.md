# Text area

> Core's Text area, compiled for the web: the `iOS=False` look at the Large text size. Generated by the Core sync; do not edit.

## Anatomy and layer tree

Text field's tree, with five changes:

1. `Character count` in the label row.
2. The Field is top-aligned, with top and bottom padding.
3. The text wraps.
4. There is no `_Unit suffix`.
5. `Status` holds the Warning glyph only.

```
Text area (variant root)           Fill × Hug, no fill, no padding, no min size (no Hit target, as Text field)
└─ Container                       VERTICAL, Fill × Hug, gap 8 (raw, as Text field)
   ├─ Label + Character count      HORIZONTAL, Fill × Hug, start-aligned, gap 8 (raw)
   │  ├─ Skeleton title            120 × 16, radius 4 (Skeleton only); first, so its bar sits at the left as Text field's
   │  ├─ Title                     TEXT, Fill, wraps (hidden on Skeleton)
   │  └─ Character count           HORIZONTAL, Hug; shown by the `Character count` property
   │     └─ Count                  TEXT, Hug, one line, never cut (hidden on Skeleton)
   ├─ Field                        HORIZONTAL, Fill × Hug, min height Text area/Field/<Size>/Layout min-height,
   │  │                            top-aligned, padding 16 all sides, gap 16, radius 8, stroke 3 (Read-only 2), no clip
   │  ├─ Text overflow             HORIZONTAL, Fill × Hug, top-aligned, padding 0 (hidden on Skeleton)
   │  │  ├─ Input text             Fill, wraps
   │  │  ├─ Input Cursor           Active with Text filled=False only, before the placeholder
   │  │  └─ Placeholder text       Fill, wraps
   │  └─ Status                    the Warning glyph (`triangle-exclamation`), on the first line
   └─ Detail                       HORIZONTAL, gap 4 (raw), hidden on Skeleton
      └─ Helper Text | Error message | Success message | Warning message, with its glyph on Error / Success
```

Sibling order in `Text overflow` is Text field's (`Input text`, `Input Cursor`, `Placeholder text`), so the empty Active field reads "|Placeholder text" as Base's does.

## Axes

| Axis | Values (default first) | Drives |
| --- | --- | --- |
| `Text filled` | False · True | Input text or Placeholder text |
| `State` | Enabled · Pressed · Focus · Active · Error · Success · Warning · Read-only · Disabled · Skeleton | colours, stroke, the Warning glyph, the Detail line |
| `Size` | Large · Medium · Small | Title and value text styles (17 · 16 · 15 pt), the Status glyph's step |

`State` is Text field's 13 without Incomplete, Complete and Loading. Those three report a format check on a short value (an ID number, an account): a glyph in the field and a spinner while a server checks. Free text has no format to check, and neither Carbon's Text area nor a product case has them. Warning and Success stay, so Detail lines work the same as Text field's.

Properties: `Character count` (BOOLEAN, default True: Carbon's `Count` and Base both show it) shows the `Character count` frame, linked in all 60 variants. On Skeleton its `Count` is hidden, so the frame is empty there; the property links a frame, not the TEXT, so Skeleton never shows a count. `Helper` (BOOLEAN, default True) hides the helper line with its `Detail` row; linked in the 36 variants where Detail holds only `Helper Text`, every State but Error, Success, Warning and Skeleton. 2 × 10 × 3 = **60 variants**.

## Component variables and Theme tokens

`Components`, Tag's three-level shape: Text field's property set under `Text area/Field/<Size>`, aliasing the same `Sizing` / `Spacing` steps where the value is the same. It never aliases a `Text field/*` variable (Existing components).

| Group | Keyed by | Properties | Values | Against Text field |
| --- | --- | --- | --- | --- |
| `Text area/Field/<Size>` | `Size` | Layout horizontal, Layout vertical | `Fill container`, `Hug contents` | same |
|  |  | Layout min-height | **104** at every Size (raw) | Text field: `Sizing/control-*` (56 · 48 · 36) |
|  |  | Padding left / right | `Spacing/spacing-05` (16) | same |
|  |  | Padding top / bottom | **`Spacing/spacing-05`** (16) | Text field: `Spacing/spacing-00` |
|  |  | Gap horizontal | `Spacing/spacing-05` (16) | same |
|  |  | Radius | `Radius/8px (radius-sm)` | same |
|  |  | Stroke weight | 3 (`Sizing/stroke-field = 3`); Read-only's 2 is a literal rule | same |
| `Text area/Icon/<Step>` | Icon step | Type token | `fa-sharp fa-solid/Large` · `/Medium` | same |

10 × 3 + 2 = 32 variables.

Why the two differ:

- **Padding top / bottom 16.** Text field centres one line in its min height, so it needs no vertical padding. A text area's lines start at the top, so the box needs its own. 16 is Base's, matches the side padding, and puts the first line where Text field Large's sits ((56 − 24) / 2 = 16).
- **Min height 104 = 16 + 3 × 24 + 16.** Body, Callout and Subheadline all have a 24 line height (ADR 0012), so 3 lines is 104 at every Size. The Sizing scale has no 104 (it stops at `control-xlarge` 64), so the value is raw, as Stroke weight is. The line count is a call for the owner: Base shows 2 (80) and Carbon about 5.

Templates:

```
Components/Text area/Field/{{Size=*}}/<Property>
Theme/<Semantic token>                 one rule per token, over the States that bind it
```

`Theme`: no `Text area/*` tokens. Each rule binds the Semantic token Carbon's Text area binds for that role. These are the same tokens Text field binds, with Base's per-state look ([text-field.md](text-field.md)). `←` means the Enabled value. A blank cell binds nothing.

The counter keeps `text-secondary` in Error, as Carbon's does. Error also covers errors that have nothing to do with length, such as a required field left empty, so a red count would mislead there. Over the limit is `State=Error` with its glyph and message: the default copy is "17 characters over the limit", "เกินมา 17 ตัวอักษร" in Thai product copy (Usage).

Pairs for the spec's `contrast` list:

- On the Base surfaces: Title, Character count and the Detail lines.
- On `Field` (each state's fill): Input text and Placeholder text.
- Non-text: the Warning glyph on `Field`, the Error and Success Detail glyphs on the surfaces, and the Focus, Active, Error and Success stroke.
- Decorative: Read-only's stroke and the fill.
- The Focus ring.

## Icon records

`Text area/Icon/<Step>/Type token = fa-sharp fa-solid/<Step>`. Beside text, the step follows the value text, as Text field's does (Icons): Large → Large (17), Medium and Small → Medium (15). The Warning glyph in `Status` takes that step. The Detail glyphs are Medium at every Size, beside Subheadline.

## Text styles, wrapping and truncation

| Layer | Text style (Large · Medium · Small) | Lines | Text property |
| --- | --- | --- | --- |
| `Title` | `Headings/Headline` · `Body/Callout` · `Body/Subheadline` | wraps (Fill, auto height) | none yet |
| `Character count` | `Body/Subheadline` at every Size | one line, Hug, never cut (a figure) | none yet |
| `Input text` | `Body/Body` · `Body/Callout` · `Body/Subheadline` | wraps: Fill, `HEIGHT`, no truncation, no `maxLines` | none yet |
| `Placeholder text` | as Input text | wraps: Fill, `HEIGHT`, no truncation | none yet |
| `Helper Text` · `Error message` · `Success message` · `Warning message` | `Body/Subheadline` | wraps, never truncates | none yet |

The Field grows with the value and has no max height in Figma. Code caps the growth and scrolls inside (an assumption).

## Hit target and Skeleton

- **Hit target**: none on the Root, as Text field (owner, 2026-11-02; ADR 0003's amendment). The Field is at least 104 tall and full width, so the tap area is already well over 48 × 48. There is no trailing action and no Clear. Status glyphs are not targets.
- **Skeleton**: `State=Skeleton`, as Text field and Carbon's Text area have. The Field takes `skeleton-background` at its min height (104), with a 120 × 16 bar for the Title. No text, counter or Detail.

The stroke is 3, not the 2 that pawisssh/design-system#171 and the Motion table name. The owner set Text field to stroke 3 on 2026-11-01 ([text-field.md](text-field.md)), and Text area copies it. The token, reduced form and haptic are as pawisssh/design-system#171 asks.

## Accessibility

- [x] 1. Each text / background pair passes in both modes: the contrast lint (`check-specs.sh`) passes `text-area.spec.json` with no defects. The pairs are Text field's plus the counter, which is `text-secondary` on the Base surfaces, as Title is.
- [x] 2. Meaningful non-text parts pass 3:1: the stroke on Focus, Active, Error and Success, the Warning glyph and the Detail glyphs (the same lint, no defects).
- [x] 3. The field is identified by more than its fill: the Title above, placeholder or value inside, and stroke 3 on Focus, Active and Error (Filled fields).
- [x] 4. No state is shown by colour alone. Error and Success carry a glyph and a message, Warning a glyph and a message, Disabled the dimmed text, Read-only its outline. Over the limit is an Error with a message, not only a red count.
- [x] 5. The Focus ring sits outside the Field.
- [x] 6. Checked on Active, Error and Warning at each Size with a long Thai value (`ปั๋ง ผู้ใหญ่ ฎู ฟุ้ง` and the long unspaced phrase), plus Small Enabled and Large Active with a long placeholder. ## Usage

- Use it for free text longer than one line: a note, a reason, an address, a message to an adviser. Use a [Text field](text-field.md) for one line, and a [Password field](password-field.md) for a secret.
- The Title always shows. The placeholder is an example, not the label.
- Turn on `Character count` when the input has a limit, and write it as `<count>/<limit>` ("0/200"). Over the limit, the field shows `State=Error` with the message "เกินมา <n> ตัวอักษร". The count stays grey.
- The field starts 3 lines tall and grows as the value wraps. In code it stops growing at 6 lines and scrolls inside (assumption).
- Use Read-only for a value the user can see but not change, and Disabled only for "can't interact".
